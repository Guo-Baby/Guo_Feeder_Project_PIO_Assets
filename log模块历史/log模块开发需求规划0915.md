# 0. 开发目标

LogManager 的设计契约已经冻结，现在正式从设计阶段进入编码阶段。

本阶段目标不是一次性完成所有 LogManager 功能，而是按照以下顺序逐步落地：

```text
P1.1
  ↓
Log Contract Header
  ↓
P1.2
  ↓
Log Core / RAM Queue
  ↓
P1.3
  ↓
Flash Segment Ring
  ↓
P1.4
  ↓
Cloud Log Topic / CBOR
  ↓
P1.5
  ↓
ACK / Retry / Offline Sync
  ↓
P2
  ↓
System / Workflow / Water / Weight / Valve 等模块接入
```

**每一个阶段都必须：**

1. 修改代码
2. 编译
3. 运行对应自动测试
4. 烧录真实 ESP32-S3
5. 进行实机测试
6. 如涉及 MQTT，必须使用真实 EMQX 服务器测试
7. 检查 Git diff
8. 提交一个独立 Git commit
9. 记录测试结果
10. 阶段通过后才能进入下一阶段

**禁止把多个阶段混在一个 commit 中。**

## 1.1 已冻结设计不得重新设计

如果发现冻结设计与现有代码存在冲突：

> 停止扩大修改范围，先报告冲突位置、原因和最小修改方案。

```text

    Cloud → Device
```


```text

```

## seq reserve

启动时：

```text
seq_base = meta.seq_reserved + 1
meta.seq_reserved += 256

```

```text

```

允许：

```text

```

