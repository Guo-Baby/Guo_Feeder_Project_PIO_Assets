### 2.2 已修 bug（★ 重要，别再踩）

**段文件必须预分配为定长 3984 B。**
首版 `flash_create_segment` 只写 16 B header，追加 9 条后文件为 1168 B
→ 重启扫描时 `size != LOG_SEGMENT_SIZE` 被判为损坏 → **整段丢失**
（实测 `valid=1, total_rec=31`，段 1 消失）。
修复：建段时把 header 之后的 3968 B 补零。未写入槽为全 0，其 CRC 必然校验失败，
因此天然表达"空槽"，无需额外标志位。

### 3.1 已实现

| 项 | 说明 |
|---|---|
| `meta.bin` | 32 B 定长：`magic(0x474C4F47 "GLOG") / fmt_version(=2) / boot_seq / seq_reserved / corrupt_count / reserved 8B / crc32[0..27]` |
| `meta_read` / `meta_write` | 整块读写 + magic / 版本 / CRC 三重校验 |
| `seq_reserve_next()` | §13：`base = seq_reserved + 1` → `seq_reserved += 256` → **立即落盘** |
| `seq_init()` | Boot 时：读 meta → `boot_seq++` → 预留一个区间（失败则 `s_seq_reliable=false`） |
| §16 恢复 | meta 缺失/损坏 → `flash_find_max_seq()` 扫描全部有效段取最大 seq → **向上取整到 256 的倍数** → 重建 reservation → `corrupt_count++` |
| 区间耗尽 | `log_emit()` 中检测 `seq_last + 1 > seq_limit` → 临界区**外**调用 `seq_reserve_next()`（Flash I/O 禁止入临界区，§3）；用 `s_seq_reserving` 门闩防重复预留 |
| 降级 | 预留写失败 → `s_seq_reliable = false` + 本地扩一段继续工作（不阻塞、不死等，§15） |
| 测试钩子 | `log_meta_wipe()` / `log_meta_corrupt()` / `log_meta_test_fail_next(bool)` |
| 控制台 | `logt meta` / `mwipe` / `mcorrupt` / `mfail <0\|1>` |

### 3.3 下一步（步骤 4：Recovery / corruption）

按 §18 / §19 / §20 实现：

1. **Header 损坏** → 删除该段 + `corrupt_count++` + 作为空段复用
2. **Record CRC 损坏** → 从该条起全部视为无效，append 从该位置重新写
3. **部分写入**（文件尾部不足一条 record）→ 该条无效，从该位置重写
4. **Ring 满** → 删除最老 segment 后复用（当前 `flash_ensure_append_target()` 在此返回 false，需改为淘汰最老）
5. 新增测试钩子：破坏段头 CRC / 破坏指定 record / 截断段文件
