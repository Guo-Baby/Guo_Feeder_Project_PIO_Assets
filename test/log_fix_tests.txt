# F5 —— FIX-4：log_ack 不得污染命令去重缓存（★ 需要 MQTT）
#
# `logt ack` / `ackauto` 直接注入 LogManager，**绕过** cloud_process_rx_message，
# 因此 F5 无法用串口验证，必须走真实 MQTT（凭据见 AI_RULES.md 末尾）。
#
# 原理：命令去重缓存只有 10 项 / 30 s TTL（MQTT_DUP_CACHE_SIZE）。
#       ACK 频率最高 1 条 / 500 ms ⇒ 若 log_ack 走去重缓存，数秒内就把它刷满，
#       把**真实命令 id 挤出去** ⇒ 同一条命令可能被执行两次。
#
# 步骤（PC 端，设备在线）：
#   1) 下发命令 id=DUPX 两次 → 第 2 次设备串口必须出现 "[Cloud] duplicate command"
#      python test/mqtt_log_probe.py raw guo_feeder/down '{"c":"system","i":"DUPX","p":{"o":"memory"}}'
#      （连发两次；注意两次间隔要 < 30 s）
#   2) 连发 15 条 log_ack（**各不相同的 i**，b/f/t 用任意值即可 —— 会被判 IGNORE，
#      但关键是它们**不得进入去重缓存**）：
#      for i in $(seq 1 15); do
#        python test/mqtt_log_probe.py raw guo_feeder/down \
#          '{"c":"log_ack","i":"AK'$i'","p":{"b":1,"f":1,"t":1}}'
#      done
#   3) 再下发 id=DUPX 一次 → 设备**仍须**打印 "[Cloud] duplicate command"
#      （若被打印，说明缓存未被 ACK 挤掉 ⇒ FIX-4 生效；
#        若命令被执行了 ⇒ ACK 污染了缓存）
#
# 串口侧可观测串：
#   [Cloud LOG] ack rx boot=%u from=%u to=%u     ← 每条 ACK 都应出现（含无 i 的情形）
#   [Cloud] duplicate command                    ← 去重命中

# F8 —— FIX-D1：补发 sweep 中删除"游标所在段"后继续前进
#
# 构造：
#   fill warn 40 + flush     → seg0=31 / seg1=9
#   creset + sonline 1       → acked=0、arm；**强制 online** 使 replay 流程可执行
#                              （replay 只在 used==0 时推进）⇒ 推 16 条后暂停，游标 = seg0@16
#   fcorrupt 0               → 段头损坏 → 扫描删除 seg0
#                              ⇒ D1：记下 seg0.first_seq 作为约束并重新 arm
#   sonline 1（幂等）+ ackauto 0 → 排空 16 条 ⇒ 补发**从 seg0 之后继续**
#                              ⇒ 命中 seg1，再推 9 条 ⇒ replay = 16 + 9 = 25
#   ackauto 0                → 再排空 9 条 ⇒ sweep 完成（rarmed=0）
#
# ⚠️ 本段验证的是"删除 replay **当前段**后的 after_seq 约束"，
#    **不验证 MQTT 离线行为**。必须 `sonline 1`：cloud_poll() 的离线分支
#    （`!force_online && !cloud_is_connected()` ⇒ return）位于 replay 调用**之前**，
#    真离线时 replay 根本不会执行 ⇒ 断言全 MISS 且 D1 的 re-arm 分支不会被触及。
#
# ⚠️ 诚实说明：本段验证的是**游标连续性与路径安全**（删除发生在 sweep 中时
#    不丢记录、不空转、不无限循环）。**旧行为在本场景下结果相同** —— 因为
#    游标只在 used==0 时前进 ⇒ 已扫描记录必已被 ACK ⇒ 即使回到最老段重扫，
#    那些记录也会被 `log_ack_should_replay()`（seq <= acked）跳过。
#    故 D1 是**预防性**修改（消除无谓重扫，并防止将来不变量变化后退化为重复投递），
#    其行为差异在板上不可观测；逻辑差异由代码审查覆盖。
# ⚠️ `fcorrupt` 是**故意破坏**段头：seg0 中尚未 push 的 15 条会随之丢失
#    （这是损坏语义，不是 D1 的缺陷）。断言只统计"仍可补发"的条数。
