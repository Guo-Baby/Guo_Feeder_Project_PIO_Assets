## 二、🔴 必须先修的前置问题（P0，安全）

**这两个不修，加控制按钮等于把放水开关挂到公网。**

### P0-1 `cloud_api` 命令通路**没有任何鉴权**

证据（`guo-feeder-api/src/index.js`）：

- 只有 `/api/history/*`（`:233`→`authorizeAdmin`）与 `/api/admin/*`（`:255`）校验
  `Authorization: Bearer ADMIN_API_TOKEN`
- 根路径 `POST /` 的 `cloud_api` 分支在 `:451` 就早退去下发，
  **位于** webhook key 校验（`:545` `if(source !== "cloud_api")`）**之前** ⇒ 完全跳过密钥
- Pages `api/command.js` 把自己标成 `source:"cloud_api"` 后直接转发，且 `/api/command`
  **不在** `PROTECTED_PAGES` 里 ⇒ **未登录也能调用**

实测：本机脚本用 urllib 直接 `POST {WORKER_BASE}/` + `{"device_id","c","i","source":"cloud_api"}`、
**不带任何 header**，连续多次返回 HTTP 200 并把命令真正下发到设备。

⇒ 任何知道 `workers.dev` 地址与 `device_id` 的人都能开阀。

**修法（三处）**

| # | 位置 | 改动 |
|---|---|---|
| 1 | Worker `index.js` `cloud_api` 分支 | 要求 `Authorization: Bearer ADMIN_API_TOKEN`，缺失/错误 ⇒ 401 `unauthorized` |
| 2 | Pages `_middleware.js` | 把 `/api/command`、`/api/command/` 加入保护集（**它是人类入口，不是机器入口**；EMQX 三条 webhook 仍然绝不加入） |
| 3 | Pages `api/command.js` | 服务端读 `env.ADMIN_API_TOKEN` 注入 Bearer，浏览器永远看不到令牌 |

★ 顺序：先 2+3 再 1（或同一次部署），否则 UI 会先断。

### P0-2 缺 CSRF / 来源校验

同源 POST 仍可能被第三方站点借 cookie 触发。加两条判定：
`Origin` 必须等于本站、`Sec-Fetch-Site` 必须为 `same-origin`（缺失时降级用 `Referer`）。
只作用于**写**入口（`/api/command`、`/api/auth/*`），不影响 webhook（本就无 cookie）。

### P0-3 命令幂等

设备侧 `cmd_id` 30 s 内重复会**静默丢弃**（无回帧）。UI 每次生成新 `i`（`crypto.randomUUID()`），
并在界面上把"已发送 / 已确认 / 已执行"三态区分开，避免用户重复点。

## 三、★★ registry 版本策略：**运行时取，绝不硬编码**

这是本项目最容易反复踩的坑：`v` 会因模块 `enable` 翻转与新 Action/Trigger 注册而递增，
今天已经历 2 → 3 → 4。

**方案**

- 新增 Worker 只读端点：`GET /api/admin/device/:id/registry?k=0|1|2`
  （内部用现有 `query` 通道向设备要 registry，**带 60 s 内存缓存**，键 = `device_id + k + boot_seq`）
- Pages 加白名单：`admin/device/<id>/registry`
- 返回形态（供 UI 直接用）：

```json
{ "v": 4, "n": 14,
  "actions": { "VALVE_OPEN": 10, "VALVE_CLOSE": 9, "WEIGHT_ZERO": 13, "TEST_STEPPER_START": 7 },
  "workflows": { "wf_valve_20g": 3 } }
```

- UI 逻辑：**所有按钮都按名字查表**（`actions.VALVE_OPEN`），查不到就禁用并提示
  "registry 版本不匹配，请刷新"。绝不出现 `v:4,k:10` 这类字面量。
- 缓存失效：收到 `e=3 s=4 version mismatch` 时立即清缓存并重取一次，成功则重发命令。

## 四、日志解码（Worker 端，唯一一份码表）

**为什么不在前端解**：前端要维护 `LOG_* → 0xNNNN` 全表（约 200 个 EventId + 参数表），
与固件必然漂移；且 CBOR 解析器要额外打包进页面。放 Worker 端只维护一处。

### 4.1 码表生成（脚本，可重复）

新增 `Cloudflare_Assets/scripts/gen-log-codes.js`（或 py）：

- 输入：`PIO_Assets/Guo_Feeder_Project/src/log/log_events.h`
- 抽取：`LOG_XXX = 0xNNNN`、`LOG_P_YYY = 0xNN`、`LogLevel` 枚举
- 输出：`guo-feeder-api/src/log-codes.generated.js`
  ```js
  export const CODES_HASH = "<sha256 前 12 位>";   // 用于漂移检测
  export const EVENTS = { 0x0509: "LOG_VALVE_OPEN", ... };
  export const PARAMS = { 0x21: "LOG_P_STATE", ... };
  export const LEVELS = ["DEBUG","INFO","WARN","ERROR","CRITICAL"];  // ★ 0 基
  ```
- **漂移检测**：`/api/history/log` 响应带 `codes_hash`；前端与 `/api/admin/metrics` 里的
  期望值不一致时在页面顶部提示"码表可能过期"。

### 4.2 解码实现

新增 `guo-feeder-api/src/log-decode.js`：

- CBOR 最小解码器（只需 uint/neg/bytes/text/array/map/null，约 60 行）
- `LogRecord` 定长 128 B 的字段偏移（`log_events.h:411-453`）：
  `[1]=level [3]=param_count [4..7]=seq [8..11]=boot_seq [12..13]=event_id [16..19]=uptime [20..23]=ts`
- 参数区从 offset 28 起，每条 6 B：`[id, type, 4B value]`，`type` 决定读法
  （`0=u8 1=i32 2=u32 3=f32 4=bool 5=enum 6=str 7=i8 8=u16`）

### 4.3 逐个已踩坑点（必须照抄，否则结果会错）

| 坑 | 正确做法 |
|---|---|
| **`LogLevel` 是 0 基** | `0=DEBUG … 4=CRITICAL`。1 基映射会把 WARN 显示成 INFO（本轮已踩） |
| **开机早期记录内 `ts=0`**（`RET-1`） | 显示时间**回退用 `created_at`**（`log_history` 是**秒**，`mqtt_messages` 是**毫秒**） |
| **`log_history` 没有 `module` 列** | 按 `module` 过滤直接报错（返回空像"没日志"）。事件名要靠解码得到 |
| **`payload` 可能是 tenant 副本/多记录信封** | 取 `env[11][0]`；缺则回退 `env[-1][0]`，两者都没有就跳过并计数 |

### 4.4 接口兼容

`GET /api/history/log` 新增可选 `decode=1`：默认行为**不变**（向后兼容），
`decode=1` 时多返回一个 `decoded` 字段（原 `payload` 仍保留，便于对拍）。

### 交互与状态约定

| 项 | 约定 |
|---|---|
| 轮询 | 状态 5 s（`snapshot` + 4 个 `query_state`）；曲线 60 s；日志 30 s；页面隐藏时全停（`visibilitychange`） |
| 断线降级 | 顶栏灰圈 + "最后成功 05:31:12"；控制按钮**全部禁用**（不允许"盲发"） |
| 二次确认 | 开阀 / 跑 workflow / 秤清零 弹确认框，明确写出"将真的放水 / 将真的清零"；关阀不拦（安全方向） |
| 操作日志 | 每次下发写 `command_audit`（§六），页面上显示"最近 5 条操作" |
| 寄存器差异 | 按钮 `k` 全从 registry 查表；查不到就禁用并提示刷新 |
| 错误呈现 | 设备回 `s!=0` 时把 `m` / `e` 原文显示出来（不吞），并把已知错误码翻译成中文提示 |
| 无障碍/移动 | 触控目标 ≥ 44 px；`prefers-color-scheme` 支持深色；表格在窄屏改卡片式 |

## 六、操作审计（二次确认的落地）

`device_event.type` 有 **CHECK 白名单**（`register/credential_*/acl_update/bind/.../retire`），
**不能**直接塞 `command_audit`。D1 也不支持改 CHECK。

⇒ 新建独立表（**纯新增迁移**，不动既有表）：

```sql
CREATE TABLE command_audit (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  device_id   TEXT NOT NULL,
  cmd_id      TEXT NOT NULL,          -- 设备侧 i（幂等键）
  kind        TEXT NOT NULL,          -- action | workflow | config_set | config_save | query
  object      TEXT,                   -- VALVE_OPEN / wf_valve_20g / weight.enable
  params      TEXT,                   -- JSON
  result_s    INTEGER,                -- 设备回帧 s（0=成功）
  result_e    INTEGER,                -- 设备回帧 e
  result_m    TEXT,
  actor_ip_hash TEXT,                 -- 与 session.js 的 ipHash 一致，不存明文 IP
  created_at  INTEGER NOT NULL DEFAULT (unixepoch())
);
CREATE INDEX idx_command_audit_dev_time ON command_audit(device_id, created_at DESC);
```

写入点：Pages `api/command.js`（转发后按设备最终 `result` 回填 `result_*`；
设备异步回帧时先落"已下发"，收到 result 再更新——若实现成本高，第一版只落"已下发"）。

## 十、风险与已知约束

| 风险 | 处置 |
|---|---|
| 加 Bearer 后 Pages 忘记注入 ⇒ 命令全 401 | M1 验收用**无害命令**（`query_state`）证明注入生效，再用**关阀**（安全方向）证明写通路通；**不要用开阀做验收** |
| registry 缓存导致刚改的 workflow 不可用 | 60 s TTL + 收到 `version mismatch` 自动重取并重试一次 |
| 日志解码码表与固件漂移 | `codes_hash` 比对 + 页面提示；生成脚本进"改 `log_events.h` 后必跑"清单 |
| 轮询压 D1 / Worker 调用量 | 状态 5 s（页面隐藏停）+ 曲线 60 s；D1 读操作免费额度充足，但要观察 |
| 手机端误触放水 | 开阀/跑流程二次确认 + 后台自动关阀保护仍在（`valve.safety_timeout_sec=300`） |
| 21 g 若在 300 s 内流不完，阀会被 `force_close` | UI 在流程运行中显示已开阀时长倒计时，接近 300 s 给出警告 |
