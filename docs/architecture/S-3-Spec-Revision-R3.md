## 1. `S-3-O2` 裁决：读路径临界区预算 10 µs → 15 µs

### 1.1 三重留痕表（禁止只留新值）

| 维度 | 值 | 状态 | 出处 |
|---|---|---|---|
| **原预算** | **≤ 10 µs** | **历史记录，保留不改写** | R1 §5 行 243 / R2 §2 `S3-U3` / 实施报告 §3.2 |
| **实测值** | **12 µs**（`snap_crit_max_us`） | **实测，永久保留，不得修改** | `docs/evidence/S-3-Flash-2026-10-20/post-flash-state.txt` |
| **新预算（R3 起）** | **≤ 15 µs** | **现行工程预算** | 本文件 §1 |
| **按旧预算的判定** | **超标 20%**（12 / 10） | **历史结论，保留** | 烧录验证报告 §5 第 1 行 |
| **按新预算的判定** | **预算内**（占 80%，余量 3 µs） | **现行结论** | 本文件 §1 |
| **门禁判定** | **与预算无关**：门禁指标是 `loop()` P99，不是临界区耗时 | **`NOT VERIFIED` 不变** | 见 §3 |

> ★★ **记述纪律**：允许写"在 15 µs 预算内"，**禁止**写"达标 / 通过 / PASS / 已解决"。
> 理由：15 µs 是**自定工程预算**，不是门禁指标；把它写成"达标"等于把自定预算偷换成验收结论。

### 1.2 采纳 15 µs 的 5 条理由

1. **实测值构成可解释**：12 µs = `esp_timer_get_time()` ×2（约 1–2 µs）+ 临界区进出 + **512 B 直方图拷贝** + 56 B 标量。纯关中断段估计 9–10 µs。
2. **仍低于通用建议**：ESP-IDF 对单次关中断的一般建议是 **< 20 µs**；15 µs 仍留 **25%** 余量。
3. **真机无危害证据**：10.4 min / 17 291 753 样本下 `ack_timeout=0`、`ack_rx=55`、`ack_ok=55`、`retry=0`、无 WDT 复位、无 panic。
4. **替代方案成本不抵收益**：改分块拷贝（8×64 B）或 seqlock 双缓冲需**改码 + 重建 + 再烧 1 次**（+1 次重启、`boot_seq` 23→24），换来 ≤3 µs，且引入"8 段跨临界区不一致窗口"的新风险类别。
5. **不触碰任何门禁阈值**：20 ms 的 P99 阈值、2 h + 30 min 的时长要求、绝对口径（`S3-Q1`）**全部不变**。

## 2. 2.5 h 正式门禁窗口 → **延期至预生产验收阶段**

### 2.1 决策

| 项 | 内容 |
|---|---|
| 决策 | **本轮不执行 2 h 稳态 + 30 min 突发**；延期至**预生产验收阶段** |
| 授权状态 | 用户于 `2026-10-20 03:05` 明确"暂时延期" |
| 设备占用 | 本阶段**不占用**设备做长窗口 |
| 数据效力 | 现有 **10.4 min / 17.29 M 样本**数据**仅为 L2 与能力证据**，**不构成门禁证据** |

### 2.2 延期的 3 条理由

1. **配置代表性不足**（见 §3）：当前窗口是在**缩减硬件配置**下取得的，直接当门禁用会系统性高估。
2. **成本不对称**：2.5 h 连续窗口需要设备专用、`boot_seq` 增加、串口单会话长跑；而配置一变就得重跑 ⇒ 在硬件未就位时跑，**大概率白跑一次**。
3. **避免把未验证的实时性结论带进生产**：用户明确要求。延期使"结论"与"适用配置"始终对齐。

### 2.3 延期后的状态（逐项，不得含糊）

| 项 | 状态 | 依据 |
|---|---|---|
| **L1**（观测能力已实现） | ✅ **真机达成** | `system.loop` 返回 `available:true / valid:true` |
| **L2**（采集有效） | ✅ **核心 4 项达成**（`Σhist+over=n` 4 快照 + 2 窗口全 PASS、`anomaly=0`、`sat=0`、覆盖率 99.9964%）；⚠️ 注入对照未做（`S-3-U6`） | 烧录验证报告 §4 |
| **L3**（P99 达标） | ⚠️ **`NOT VERIFIED`——不因延期而改变，也不因 10 min 数据好看而改 PASS** | 时长 10.4 min ≪ 2 h + 30 min |
| **`G-4` 第 1 项（`loop()` P99 劣化）** | ⚠️ **`NOT VERIFIED`**（能力已具备 + 有初值，**缺正式窗口**） | `BT-1-Acceptance-Report.md` §6.4 `GATE-WP5` ② |
| **`G-4` 整体** | **`BLOCKED`** | 另有 `G4-R4`（DRAM 口径）独立未决 |
| `WP-5` / `BT-1` / `STOP-R1` | **未解锁 / `CLOSED` / 无解除** | 均未变动 |

### 2.4 恢复条件（**5 条全部满足**才可启动该窗口）

1. **硬件 bring-up 完成并稳定**：§2.5 表中标为「必须」的器件已在位且自检通过；
2. **配置快照固定并入库**：窗口开始前导出 `config_query` 全量（哪些模块 `enable=true`），写入证据目录；**窗口期内禁止改配置**；
3. **单独授权**：2.5 h 连续窗口由用户**单独**授权（不与其它任务混跑）；
4. **新 boot 周期基线**：`minimum_free` 等**只能在同 boot 内比较**，窗口必须从新 boot 起算；
5. **设备专用**：窗口期间不做烧录、不做配置变更、不做执行类动作测试。

### 2.5 配置代表性要求（**这是"要不要挂全部器件"的正式答案**）

| 器件 | 固件模块 | loop 内行为（已只读核实） | 对 P99 的影响 | 门禁窗口是否必须在位 |
|---|---|---|---|---|
| **电子秤 HX711** | `weight.cpp`（`weight.enable`） | `is_ready()` 门控，10 Hz 取样；`read()` 内部为 `while(!is_ready()) delay(0)` **无超时** | 正常 ≈百 µs 级；★ **掉线可无限阻塞** | **必须**（生产配置含它，且它是唯一能"卡死 loop"的器件） |
| **RTC** | `time_manager.cpp`（`rtc.enable`，I2C `0x51`，自写驱动无外部库） | 仅 init 探测 + SNTP 校准写入（偶发） | 极小 | **必须**（校准写是真实偶发 I2C 事务，需被覆盖） |
| **电磁阀** | `valve.cpp`（`valve.enable`） | **纯状态机，无 `delay`/`while`** | 硬件动作不产生 loop 负载 | **必须挂**，但**不必动作**（让状态机与安全超时逻辑在真实条件下运行） |
| **电机 / 步进** | ❌ **固件中不存在**（仅 `log_events.h` 预留 `0x0Fxx Motor` 段） | 无 | 无 | **无法挂**——没有驱动代码。挂上也不产生任何 loop 负载，只会让"已覆盖"变成假象 |
| **OLED** | `oled.cpp`（**无 enable 门控**） | 每 `frame_delay`（默认 50 ms）刷新整帧；`oled_speed=100000` | ★ 若真在传输：**每帧 92–184 ms**（见 §3） | **必须在位并实测**；★ 见 §3 的阻断性风险 |
| **MI 温度计** | `MiThermometer.cpp`（BLE） | BLE 扫描/事件 | 未知，需实测 | **建议在位**（BLE 事件时序可能制造长尾） |

> ★ 结论：**"挂全部器件"不是形式要求，而是"测量对象必须等于生产对象"的要求**。
> 唯一例外是**电机**——它在固件里还没有代码路径，挂与不挂对 `loop()` 的负载**完全等价**。

### 2.6 明确禁止的做法

- ❌ 用当前 10.4 min / 缩减配置的数据**折算/外推**成门禁结论；
- ❌ 窗口期内改配置（中途 `enable` 变化 ⇒ **整段数据作废**）；
- ❌ 只挂部分器件却把结论表述为"生产配置已达标"；
- ❌ 因为"10 分钟 P99 很漂亮"而把 L3 记成 PASS。

## 3. 本轮新增观察：`S-3-O3`（配置代表性缺口 + OLED 阻断性风险）

**这是本轮最重要的技术发现，且是 INFERRED（由实测反推），不是直接测量。**

### 3.1 推理链

1. 实测：`n = 17 291 753`，`elapsed ≈ 621 s` ⇒ 轮转率 ≈ **27 840 轮/s**，平均 **35.9 µs/轮**。
2. `oled.cpp` 每 `frame_delay`（默认 **50 ms**）调用一次整帧刷新；`oled_speed = 100000`（100 kHz）。
3. 128×64 单色 = **1 024 B**。SSD1306 经 I2C 时每数据字节还需 1 个控制字节 ⇒ 线上 **2 048 B**。
   - 按纯数据计：1 024 × 9 bit / 100 kHz ≈ **92 ms**
   - 按含控制字节计：2 048 × 9 bit / 100 kHz ≈ **184 ms**
   - 即便把 I2C 提到 400 kHz：**23–46 ms**
4. **矛盾**：若 OLED 真在传输，loop 轮转率不可能 > 11 Hz（≈92 ms/轮），与实测 27.8 kHz **相差 3 个数量级**。

### 3.2 结论

| # | 结论 | 证据等级 |
|---|---|---|
| a | 本轮 10.4 min 窗口内 **OLED 未在实际传输**（未接屏 / 无 ACK 器件） | **INFERRED**（由轮转率反推） |
| b | 同一窗口内 `weight.enable=false`（无秤）⇒ 秤路径**未运行** | 配置事实 + INFERRED |
| c | 因此 **"P99 < 0.2 ms" 是缩减配置下的结论**，**不得**表述为"生产配置实时性良好" | 结论 |
| d | ★ **若上板后 OLED 实际传输**，在当前 100 kHz 下**单帧 92–184 ms ⇒ 20 ms 门禁不可能通过**；提到 400 kHz 仍 23–46 ms | **风险预告**（计算，非实测） |

### 3.3 处置

- `S-3-O3` 登记入 `docs/issues/未修复的问题.md`（观察级，**非 S-3 引入**，是 S-3 第一次让该缺口可见）。
- **门禁窗口必须在生产配置下重跑**，并把配置快照写入证据（§2.4 第 2 条）。
- **OLED 议题独立立项**（不在本修订内动）：可选路径 = ① I2C 提速至 400 kHz（仍可能超 20 ms）② 局部分块刷新（只刷变化区）③ 把帧刷新移出 `loop`（独立任务）④ 重新讨论"该设备是否装屏"。**四者都涉及产品决策或架构变更，需单独裁决。**
