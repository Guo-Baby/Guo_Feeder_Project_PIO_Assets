# S-3 规格修订 R2（`loop()` 耗时观测）

> 基线文档：`docs/architecture/S-3-Loop-Timing-Observability-Investigation-and-Spec.md`（下称 **R1**，commit `d595997`）。
> 本文 = R1 的**正式修订记录**（下称 **R2**）。R1 原文**保留不改写**（历史证据不可追溯修改）。
> ★ 修订原则：只解决**不影响安全边界**的技术决策；涉及门禁语义的项**逐条留痕**，不静默替换。
> 执行时间：`2026-10-20 02:05 – 02:2x`（本地）。本文件**不含**任何设备/云端变更。

---

## 0. 修订摘要（一句话）

R1 的 10 个待裁决项中，**8 项**按任务书默认值关闭、**2 项**（`Q1`/`Q2`）闭合为"绝对阈值为主判据 + 相对口径留档但无分母"；同时因 **1 KB 栈铁律**把直方图几何从 `256×0.2 ms / uint16` 改为 **`128×0.2 ms / uint32`**（`S3-D1`），并把"采样率自洽"的校验量从 **P50 改成精确均值**（`S3-D2`）。门禁状态与阈值**未改动**。

## 3. 相对 R1 的技术偏离（必须显式记录）

### `S3-D1` 直方图几何：`256 × 0.2 ms / uint16` → **`128 × 0.2 ms / uint32`**

| 维度 | R1 方案 | R2 方案 | 理由 |
|---|---|---|---|
| 桶数 | 256 | **128** | 快照结构要能放在**命令处理栈帧**上（`loopTask` 栈 16 KB，但项目硬性铁律是单对象 **>1 KB 禁上栈**）。256×uint32 会到 1088 B，超铁律 |
| 桶宽 | 0.2 ms | **0.2 ms（不变）** | 保证 **20 ms = 100 × 0.2 ms 仍恰在桶边界**，判定精确无插值歧义 |
| 量程 | 51.2 ms | **25.6 ms** | ≥25.6 ms 的样本进 `over` 桶，但 `max_us` **始终精确** ⇒ 溢出区间也不会只报一个下界 |
| 元素类型 | `uint16`（饱和 65535） | **`uint32`** | ★ **R1 的 uint16 存在"提前饱和"缺陷**：1 kHz 下 2 h ≈ 7.2×10⁶ 样本，P50/P99 所在桶必然远超 65535 ⇒ 正式窗口内 P99 会**静默失真**。uint32 上限 4.29×10⁹ ≈ 49.7 天 @1 kHz |
| 结构体积 | ≈544 B | **576 B**（实测 `sizeof` = 576） | 仍 < 1 KB，`static_assert` 硬约束 |
| 饱和处置 | 置 `sat` 并"降级标注" | **置 `sat_buckets`（按不同桶去重计数）并直接拒绝输出 P99** | 任务书要求"若使用饱和计数，必须明确标记并**拒绝输出误导性的有效 P99**" |

### `S3-D2` 采样率自洽校验：`n / Δuptime ≈ 1 / P50` → **`n / Δelapsed ≈ 1 / mean`**

任务书明确要求"不能以 P50 直接替代平均周期"。R2 改为：
- 输出 **精确均值** `mean_us = sum_us / n`（`sum_us` 为 **uint64**，不溢出）；
- 自洽校验用 `n / elapsed` vs `1 / mean`（宿主机探针 `T9` 实测偏差 983 vs 984 /s，**0.1%**）。

### `S3-D3` `elapsed_us` 用 `uint64`

R1 未明确类型。若用 `uint32` µs，则 **71.6 min 回绕** ⇒ 2 h 窗口的 elapsed 会归零、`n/elapsed` 自洽校验失效。R2 定为 `uint64_t`。

### `S3-D4` `anomaly` 的定义保持 R1 原样，但把后果写明

`dt ≤ 0` 或 `dt > 60 s` ⇒ 计入 `anomaly` 且**不入 n / sum / min / max**。
因此 `sum_us` 与 `elapsed_us` 的差额就是"未被统计覆盖的时间"——这是 L2 有效性的**可独立核算**证据，而不是自证。

## 4. 端口 / 接口契约（R2 定稿）

### 4.1 命令

```json
{"c":"system","i":"<唯一ID>","p":{"o":"loop"}}
```

**只读**，无参数。与 `system.stats` 完全并列（新 object），不改动其字段。

### 4.2 响应（可信时）

```json
{"status":"success","data":{
  "available":true,"enabled":true,"scope":"uptime",
  "uptime_ms":..., "elapsed_ms":...,
  "bucket_width_us":200,"bucket_count":128,"over_limit_us":25600,
  "min_samples":10000,"gate_p99_us":20000,
  "samples":N,"over":0,"anomaly":0,"sum_us":S,"mean_us":M,"min_us":..,"max_us":..,
  "sat_buckets":0,"n_saturated":false,"snap_crit_max_us":..,"snap_count":..,
  "valid":true,"window_samples":N,"window_over":0,"window_anomaly":0,
  "p50_bucket":..,"p50_low_us":..,"p50_high_us":..,"p50_us":..,
  "p99_bucket":..,"p99_low_us":..,"p99_high_us":..,"p99_us":..,"p99_lt_gate":true,
  "hist":[bucket,count, ...],"hist_pairs":K
}}
```

### 4.3 响应（不可信时 —— **拒绝输出误导性 P99**）

```json
{"data":{
  "available":true,"valid":false,"quantiles_suppressed":true,
  "invalid_reasons":["insufficient_samples"],   // 或 bucket_saturated / counter_regression / ...
  ...计数照常输出（samples/over/anomaly/sum_us/mean_us/min_us/max_us）...,
  "p99_overflow":true,"p99_lower_bound_us":25600,"p99_max_us":61000   // 仅在 P99 落在溢出区间时
}}
```
★ **`valid:false` 时绝不出现 `p50_us` / `p99_us` 字段**。没有数字就没有被误引用的可能。

### 4.4 字段语义边界（禁止误读清单）

| 字段 | 语义 | **禁止**的解读 |
|---|---|---|
| `scope:"uptime"` | **自首个样本起的累积**，不是"窗口" | 当成"本次测试窗口的 P99" |
| `min_us` / `max_us` | 累积极值（**非窗口值**） | 与窗口 P99 混用 |
| `p50_us` / `p99_us` | **桶上界（不含）**，保守值 | 当成点估计、或做 <0.2 ms 精度的比较 |
| `p99_lt_gate` | `P99 < 20 ms`（桶边界精确） | 当成"门禁已通过"（还缺时长与对照） |
| `snap_crit_max_us` | **读路径**开销（命令上下文） | 当成采样热路径开销（后者无出口） |
| `mean_us` | 精确均值 `sum/n` | 当成 P50 |
