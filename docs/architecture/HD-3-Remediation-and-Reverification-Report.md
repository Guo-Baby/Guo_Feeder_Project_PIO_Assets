## 4. C-4 重试测试：真实 D1 与测试替身的覆盖边界

### 4.1 为什么真实 D1 覆盖不了重试

`persistConflictEvents()` 的「一次有界重试」仅在 D1 抛**瞬时错误**（`D1_ERROR` / timeout / 5xx / 429）时触发。  
本夹具用 `wrangler dev --local`，Worker 运行在 dev 进程**内部**，`env.guofeeder_DB` 绑定**不可从外部替换** ⇒ **无法注入瞬时 DB 故障**，也就造不出"第 1 次失败 / 第 2 次成功"。

> 这不是实现缺陷，是本地环境的能力边界。**不得**用"表改名"冒充瞬时故障——那是 `no such table`，属**不可重试**路径（已由 `L-7` 覆盖）。

### 4.2 覆盖分工（已在脚本与 README 中固化）

| 维度                                                | 真实 D1（`log_conflict_real_d1.sh`） | 逻辑替身（`log_conflict_retry.test.mjs`） |
| ------------------------------------------------- | -------------------------------- | ----------------------------------- |
| 冲突落库 / 唯一键 `ux_lc_key`                            | ✅ L-2/L-3                        | —                                   |
| 幂等聚合（`seen_count` 累加、行数不变）                        | ✅ L-4/L-5                        | ✅ E4                                |
| 冲突**不**写 `log_history`                            | ✅ L-8                            | —                                   |
| 表缺失 ⇒ 熔断 + HTTP 语义不变                              | ✅ L-7                            | ✅ F1–F3                             |
| **错误分类**（可重试 vs 不可重试）                             | ❌ 无法构造                           | ✅ A1–A9                             |
| **重试 1 次**（attempts 1→2、`retried`、`retry_reason`） | ❌ 无法构造                           | ✅ B4–B9                             |
| **两次失败** + `evidence-lost` 只 1 行                  | ❌ 无法构造                           | ✅ B10–B12                           |
| **`conflict_retried` 只在真重试时反映**                   | ✅ L-9a（正常路径恒 0）                  | ✅ B4/B10                            |

### 4.3 本轮新增的 `L-9` 是什么（以及不是什么）

**不是**重试测试，而是**边界声明 + 等价安全性质**：

- `L-9a0`：正常路径确实产生了 summary 样本（7 条）——防止"0 = 0"式空跑误判；
- `L-9a`：全部样本 `conflict_retried=0`（7/7）⇒ 该计数无统计错位；
- `L-9b`：冲突表最终仍 **2 行**（重试/熔断流程未污染聚合）；
- `L-9c`：`conflict_key` 去重后仍 **2 个**（无因重放而新增键）。

⇒ 即"**若**重试发生，其写入必须幂等"这一性质被真实 D1 见证；而"重试**是否**发生、发生几次"由替身见证。**两者不得互相冒充。**
