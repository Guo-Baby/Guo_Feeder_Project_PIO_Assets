## 5. 实施步骤与阶段依赖

```
S0 前置核验（阻塞性）
 └─> S1 log 面实测 ──┐
     S2 账户级额度 ──┤
     S3 字节/行 ─────┼─> S5 与估算对照 ──> S7 报告 + 校准建议
     S4 11 台外推 ───┘                      ↑
     S0b telemetry 面（可能 BLOCKED）──> S6 H-1 X 校准 ──┘
```

### `S0` 前置核验（**不做完不得进入 S1**）

1. 复核三仓 `git status` / HEAD（与 §3 一致；**不修改**）；
2. 复核线上 Worker 版本 = **`72023596-657a-4a65-aa62-81848540f324`**（`wrangler deployments list`）；
3. 复核 `[triggers] crons = ["0 3 * * *"]`；
4. **定性 `Q-2`**（遥测停更）：优先**只读**手段 —— 经既有下行链路发 **1 条 `config_query`**（`{"c":"command","i":"<new>","p":{"module":"cloud","key":"telemetry_enable"}}`，**只读**，见 §6.2 的取值依据）；若不允许发命令 ⇒ 退化为 `BLOCKED`，并在报告中标 `UNKNOWN`；
5. 记录 `SHOW`/`PRAGMA` 级基线（`table_info` / `index_list`）。

### `S1` · log 面实测（**可立即执行**）

- 按 `date` 统计 **`ts>0`** 行数；分 `level`；同时输出 `ts=0` 隔离区行数；
- 统计"有数据小时跨度"（`MIN/MAX(ts)` 按天），换算 **行/小时**，再折算"若全天在线"的上界；
- 输出 `payload` 体积分布（`MIN/AVG/MAX`，按 `level`）。

### `S2` · 账户级额度（**可立即执行**）

- `d1 info` 采样 **t0 / t1**（间隔 ≥ 30 min，且 t0–t1 之间**至少一次真实设备上传**）；
- 计算 `Δrows_written` / `Δ` 时间 ⇒ **行/天**净速率；
- **扣减声明**：本 WP 自身的 `SELECT` 不计入 `rows_written`；`wrangler d1 execute` 的元查询**计入 `rows_read`** ⇒ 必须说明读取量的非业务成分。

### `S3` · 字节/行（**可立即执行**）

- 逻辑：`SUM(LENGTH(...))` + 固定列宽（`INTEGER` 8 B ×3 + `TEXT` 头开销）⇒ **逻辑字节/行**；
- 物理交叉核对：`database_size(t1) − database_size(t0)` ÷ 新增行数 ⇒ **含索引与页开销的物理字节/行**；
- 两者差异必须解释（索引 5 个 · `AUTOINCREMENT` 表 · 空闲页）。

### `S4` · 11 台外推（**可立即执行，但必须标 `PROXY`**）

- 输入：单设备典型日 / 峰值日（`S1`）；
- 假设（**逐条写明**）：① 设备负载线性可加；② 同型号同策略；③ 峰值不同时发生（并给"同时峰值"的悲观界）；
- 输出：**典型 / 悲观**两档，× 11，对照：`100k 行写/天` · `5M 行读/天` · `5 GB 存储`
  （**免费额度取官方文档口径，未在本项目实测** ⇒ 报告中须标 `DOCUMENTED`，不得写成"已核实"）。

### `S0b` / `S6` · telemetry 面与 `H-1` 校准（**可能 `BLOCKED`**）

| 条件 | 处置 |
|---|---|
| `telemetry_enable = true` 且窗口内**有** `weight.value` 行 | 可做：用 `value` 的日间变化分布给 `X` 建议值（**须给分布，不得只给均值**） |
| `telemetry_enable = false` | **`BLOCKED`**：不得开启（属设备配置变更，**须人工授权**），`X` 校准标 `BLOCKED` |
| `telemetry_enable = true` 但窗口内无 `weight` 行 | **`UNKNOWN`**：无法区分"无变化"与"未上报"，标 `NOT RUN` |

> **★ 铁律**：`X` 的数值**不得**由代码默认值或文档推导"补出来"。**没有实测分布 ⇒ 就是 `BLOCKED`。**

| **口径自证** | 同一指标用**两种写法**（`GROUP BY date` vs 逐日 `WHERE ts BETWEEN`）算出的值一致 | 两段 SQL + 结果 |
| **交叉核对** | 逻辑字节/行 vs 物理字节/行 差异已解释 | §5 `S3` 两张表 |
| **回归（可选 · 只跑不写）** | `NODE_BIN=... node test/run_all.mjs` **仍应 15/15 `exit=0`**（证明未破坏既有测试） | 汇总行 |
| **构建（可选 · 不部署）** | `wrangler deploy --dry-run` 应**仍为 106.61 KiB**（证明本 WP 未碰代码） | 输出 |
| **未执行项** | 任何未做项必须标 `NOT RUN` + 原因 | 报告 §6 |

## 10. 模块边界、协议兼容性与架构约束

| 约束 | 内容 |
|---|---|
| **写入边界（`DT:WP-4`）** | 1 条 MQTT 消息 = 1 行；**Worker 不做业务过滤** ⇒ 行数 ≈ 消息数（`F-C2-8` 后 `INFO` 亦落库） |
| **降频唯一权威（`WP-1`）** | 降频**只能在设备侧**；本 WP **不得**提出"Worker 侧过滤"方案 |
| **保留策略（`WP-3`/`WP-7`）** | 窗口 `90 / 180` 天 · `scheduled cleanup job` · **不新增索引** · 分批 `LIMIT 1000` · 全局预算 `45`（不可达） |
| **索引集合（`WP2 §5`）** | 当前**恰好 5 个**；`ix_lh_device_level_ts` **未建**（暂缓）；本 WP 只能给结论 |
| **设备身份（`P0 §13`）** | `device_id` = 12 位小写 hex；`device_id` **不是普通配置**（不得当 Config 参数改） |
| **时间口径** | `ts` = 设备观测时刻（Unix 秒）；`created_at` = 入库时刻（D1 生成）；**两者不得混用**做日界 |
| **协议兼容** | 不改 envelope 字段、不改 `log_ack` 载荷、不改 topic 结构 |
