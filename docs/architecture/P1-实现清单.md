## 0. 冻结基线（P1 Baseline）

| 项 | 值 |
|---|---|
| **P1 目标** | 设备从"身份隔离"升级到"**生命周期管理**"（注册 → 凭据 → 授权 → 绑定 → 状态） |
| **凭据模型** | **一台设备一套凭据**（`username = dev_<device_id>`，密码云端随机生成） |
| **授权模型** | **device_id 驱动**：建账号 → 写 ACL（三条 V3 topic）→ 落库 → 下发凭据 |
| **平台约束** | EMQX Serverless 白名单模式；**不支持**外部 HTTP 认证 ⇒ 凭据只能"账号 + API 改写 ACL" |
| **设备侧身份** | **不变**：`device_id` 仍 MAC 派生 + NVS `gfid`（P0 冻结，P1 不得触碰） |
| **遥测** | **不在 P1**（大规模存储属 P3）；P1 只落 heartbeat **策略落点**（`mqtt.json.telemetry`） |
| **OTA** | **不在 P1** |

### 0.1 P1 范围边界（防蔓延）

**包含**：device registry · credential model · ACL dynamic authorization · heartbeat 基础 ·（支撑）绑定语义

**不包含**：APP UI · workflow 云端编辑 · telemetry 大规模存储 · OTA 系统 · 支付/用户体系 · 身份迁移

（**生产模式检查已裁决纳入 P1** —— 见 P1-7；**OTA / Telemetry 仍在排除外**）

### P1-3 设备侧凭据存储与轮换（**固件**）

| 字段 | 内容 |
|---|---|
| **目标** | 设备安全保存并轮换 MQTT 凭据；**不触碰 P0 的 `device_id`** |
| **预期修改** | 固件：新增 NVS namespace（建议 `gfcred`）+ 凭据读取/写入层；`cloud_manager` 的凭据来源改为"凭据存储优先、配置兜底"；新增下发入口（经 CommandManager，**不得**跨层） |
| **关键设计** | **双 slot 模型**（`slot0`/`slot1`，各带 `username/password/version/state`，`state ∈ {ACTIVE, TESTING, INVALID}`）：新凭据先写另一 slot 置 `TESTING` → 试连 → **CONNACK 成功**才置 `ACTIVE` 并把旧 slot 置 `INVALID`。⚠️ **网络失败（超时/DNS/TLS）不得误判为凭据失败** |
| **禁止** | 不得在串口打印明文凭据（沿用 P0 的安全边界）· 不得把凭据混入 `gfid` 身份 namespace |
| **风险** | ①写坏 ⇒ 设备失联（需保留串口重配恢复通道）②轮换窗口内新旧凭据并存（ACL 侧需同时允许） |
| **验证** | 串口用例：写入 → 重启 → 生效；**断电模拟**（写入后立即复位）→ 仍能连上；轮换后旧凭据失效 |


> **为什么 Phase C 把 P1-2 与 P1-4 合并**：注册（发现设备）与签发（给身份）是**同一闭环的两半**，
> 分开做只会得到"能发现但不能授权"或"能授权但无触发点"的半成品。

> ⚠️ **进入 Phase D 前**：P1-2/P1-4（云端）与 P1-3（固件）**都必须先出实施计划、经人工审核后才编码**；
> Phase C 的 `§Architecture Freeze Decision`（Q1–Q8）为不可擅改基线。
