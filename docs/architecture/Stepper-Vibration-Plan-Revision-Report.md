## B. 主要修订项

### B1 — 步进 Action 由 3 个改为 **2 个业务 Action**

- **原问题**：原计划注册 `STEPPER_ROTATE` / `STEPPER_STOP` / `STEPPER_ENABLE` 三个；
  其中"普通旋转"与"人工调整"合并为同一个含义不清的 `STEPPER_ROTATE`。
- **改为**：

| Action | 参数 | 语义 |
|---|---|---|
| `STEPPER_DISPENSE_ROTATE` | **无** | 出粮：固定 120°，脉冲数由误差分配算法决定；成功后模块自行结束，Workflow **无需**再发关闭 Action |
| `STEPPER_ROTATE_STEPS` | `pulses`（**必填**） | 人工调整：输出指定数量的**有效 STEP 上升沿**（非 GPIO 翻转次数） |

- **停止/禁用不再是业务 Action**：改为模块内部能力，由超时、异常路径与
  `disable_after_move` 配置驱动。
- 同时新增 §9.4 明确**不新增第三个急停 Action**（见 B7）。

### B2 — 新增 120° 脉冲计算与量化误差补偿（§8.3，本次重点）

原计划**完全没有**这一节。本次新增并做完整数学验证，见 **C 部分**。

### B3 — DRV8825 初始化时序与 100 Hz 脉冲输出（§10.0 / §10.1 / §10.2）

- 新增 §10.0：依据 TI DRV8825 数据手册核对引脚有效电平与时序参数（见 **D 部分**）；
- 修订 §10.1：脉冲频率定为 **100 Hz**（周期 10 ms），533 脉冲 ≈ 5.33 s；
- 修订 §10.2：补充 **100 Hz 下软件定时的定量分析**，证明即便频率低仍不可靠
  （6.4 ms 阻塞 ⇒ 抖动 64%）。

### B4 — 30 秒动作上限、critical operation、定时器竞争（§12.5 / §12.6 / §12.7）

- 新增 §12.5：统一 **30 s**，由**模块层**执行；代码硬限制
  `STEP_HARD_MAX_ACTION_MS = 30000`，配置值钳位；防重复完成机制；
- 新增 §12.6：使用正式接口 `system_command_critical_operation_acquire/release`
  （`system_command.h:130/139`），三条结束路径统一释放；
- 新增 §12.7：定时器回调**只置标志**，`stepper_task()` 统一提交与释放，
  明确"停止定时器 → 置标志 → 提交 → 释放"顺序。

### B5 — 振动模块改为双马达独立控制 + 30 s（§3.2 / §5.2 / §11）

- GPIO：新增第二路（储粮舱 16 / 坡道 **17**）；
- 配置：`relay_pin` → `hopper_pin` / `ramp_pin`（含各自 `active_level`）；
  `safety_timeout_ms` 60000 → **30000**；
- 行为：每路独立状态机、独立 30 s 超时、独立防风暴计时；停一路不影响另一路；
- 明确区分「模块超时保护 / Workflow 定时等待 / Workflow 步骤顺序」三类。

### B6 — 新增 Workflow 业务流程（§11.5）

按任务书 §7 给出 8 步流程，并明确哪些是 Action、哪些是 Timer Trigger（见 **E 部分**）。

### B7 — 新增急停/取消机制（§9.4）与最终验收清单（§13.5）

- §9.4：不新增第三个 Action；运行中动作受「模块 30 s 超时 + Action `reset()` 收尾 +
  引擎超时 + critical operation」约束；取消的正确实现位置是 `reset()`

## C. 关键计算验证

### C1. 基础计算（核对任务书 §3.1 结论：正确）

```
整步角 1.8°  ⇒ 每圈整步 = 360/1.8 = 200
1/8 微步     ⇒ 每圈脉冲 = 200 × 8 = 1600          ✓ 与任务书一致
每脉冲角度    = 360/1600 = 0.225°
120° 理想脉冲 = 1600 × 120/360 = 1600/3 = 533.333… ✓ 与任务书一致
```

⇒ 单次 120° **无法**用固定整数脉冲精确表示（533 = 119.925°，534 = 120.15°）。

### C2. 不补偿的后果

固定取 533 ⇒ 每次欠 1/3 脉冲 ⇒ n 次欠 **n/3 脉冲**（n×0.075°）；
100 次后欠 33.3 脉冲 = **7.5°**，误差**无界增长**。

### C3. 两方案比较

**方案 1（采用 ✅）：累计余数 / 误差分配**

```
target_total(n) = floor(n × 1600 / 3)
pulses(n)       = target_total(n) − issued_total
```

逐次（n=1…6）：**533, 533, 534, 533, 533, 534**

| n | floor(n×1600/3) | 本次 | 累计 | 累计误差 |
|---|---|---|---|---|
| 1 | 533 | 533 | 533 | 0.333 |
| 2 | 1066 | 533 | 1066 | 0.667 |
| 3 | 1600 | **534** | 1600 | **0** |
| 4 | 2133 | 533 | 2133 | 0.333 |
| 5 | 2666 | 533 | 2666 | 0.667 |
| 6 | 3200 | **534** | 3200 | **0** |

**数学验证（非仅凭示例）**：

- 误差 = `n×1600/3 − floor(n×1600/3)` = `frac(n×1600/3)` ∈ **[0, 1) 脉冲**
  ⇒ **累计误差上界 = 1 脉冲 = 0.225°，与 n 无关（有界，不累积）**；
- 闭合性：3 次累计 = 1600 脉冲 = 360° = 3×120° ⇒ **完全吻合，每 3 次归零**；
- 用整数运算（`n×1600/3` 的整数除法），避免浮点累积误差。

**方案 2（不采用 ❌）：事后反向补偿**

- 反向脉冲同样只能取整 ⇒ 只是把量化误差搬到反方向，**未消除**；
- 引入额外机械往复动作（磨损/噪声/时间）；
- 对三瓣拨片，0.225° 级反向微步无实际校正意义；
- 方案 1 已将误差压到 ≤0.225°，反向补偿收益远小于代价；
- 任务书 §3.3 明确要求：采用误差分配后**不得**再加反向补偿。

⇒ **决定：方案 1，且不再加入任何反向补偿动作。**

### C4. 两个 Action 的独立语义（不混淆账本）

| Action | 更新误差账本？ | 脉冲来源 |
|---|---|---|
| `STEPPER_DISPENSE_ROTATE` | **是** | 算法算出（533/534） |
| `STEPPER_ROTATE_STEPS` | **否** | 用户 `pulses` 原样输出 |

⇒ 人工调整脉冲**不进入** 120° 累计补偿账本。

### C5. 能力边界（如实表述）

该机制**只**使累计量化误差**有界**（≤1 脉冲 / 0.225°）。
**不能**检测或纠正：失步、机械滑动、传动间隙、拨片实际位置偏差、断电后位置变化。
仍为**开环**设计，不新增编码器。
计划中已加入表述纪律：不得写成「保证真实机械位置永不偏移」。

## D. 关键时序与生命周期

### D1. DRV8825 初始化顺序（依据 TI DRV8825 数据手册）

| 引脚 | 有效电平 | 手册依据 | 核对结论 |
|---|---|---|---|
| `nENBL` | **低使能、高禁用** | 低有效（内部下拉） | ✅ 任务书预期正确 |
| `nSLEEP` | 高工作 / 低睡眠 | 低有效（内部下拉） | ✅ 需外部确保为高 |
| `nRESET` | 高正常 / 低复位 | 低有效 | ✅ 需外部确保为高 |
| `DIR`→`STEP` | 建立时间 **200 ns**（最小） | — | 固件写 DIR 后间隔 ≫200 ns ✅ |
| `STEP` 脉宽 | **1.9 µs**（高/低各，最小） | — | 100 Hz 下 5 ms，裕量 >2000× ✅ |
| 唤醒等待 | **1 ms**（t_wake，最大） | — | 任务书 50 ms = **应用层保守等待**（50× 裕量），合理 ✅ |

采纳顺序（核对结论：任务书预期顺序**成立**，仅补两处细节）：

1. EN 高（禁用）+ STEP 置 LOW —— **先写电平再 `gpio_config()`**（防配置瞬间产生上升沿）
2. 设置 DIR / nSLEEP / nRESET 及细分（M0-M2 固定接线）
3. 确认 SLEEP/RESET/细分满足工作要求
4. EN 拉低（使能）
5. 等待 **50 ms**
6. 确认 DIR，然后输出 STEP
7. 完成后按 `disable_after_move`（默认 true）禁用驱动器

补充细节：① 先写安全电平再配置输出；② DIR 在 EN 使能前设置、步骤 6 再确认一次
（防方向错误）。

### D2. STEP 脉冲输出方式与理由

- 频率 **100 Hz**，每**上升沿 = 1 个微步**，533/534 脉冲 ≈ 5.33/5.34 s；
- **必须硬件外设**：G-4 实测 OLED `sendBuffer()` 每 50 ms 同步阻塞 loop **6.4 ms**。
  即便 100 Hz（周期 10 ms）不会漏脉冲，仍会造成 **64% 抖动**
  （任务书明确禁止因频率低就认定软件定时可靠）；
- 推荐 `esp_timer` 周期回调（工程已用 `esp_timer.h`），备选 `gptimer` / RMT，
  均 ESP-IDF 自带，**不引入第三方依赖**。

### D3. Action 正常结束 / 失败 / 超时

- 三条路径统一走**一次性提交函数** `stepper_finish(result)`，
  首行 `if (!action_active) return;` ⇒ **杜绝重复完成、重复释放、重复通知 Workflow**；
- 超时处理顺序：**停脉冲 → 置 `action_active=false` → 提交 FAILED(timeout) → 释放 critical op**。

### D4. 30 秒动作限制

- 统一 30 s（120° 出粮与指定脉冲数均适用）；5.33 s 只是**预计耗时**不是超时值；
- **由模块层执行**（`stepper_task()`），关键依据：`COMMAND_ACTION_TIMEOUT_MS = 600000`
  （10 分钟，`command_manager.cpp:84`）⇒ 引擎超时**不能**替代模块限制；
- 代码硬限制 `STEP_HARD_MAX_ACTION_MS = 30000`，配置值钳位（不只依赖配置）。

### D5. critical operation 登记与释放

- 正式接口：`system_command_critical_operation_acquire()` /
  `system_command_critical_operation_release()`（`system_command.h:130/139`）；
- 脉冲输出期间登记；**正常完成 / 失败 / 超时**三条路径均在 `stepper_finish()` 内释放
  （该函数只执行一次）⇒ 不漏释放、不重复释放；
- 不复制系统级机制。

### D6. Workflow 失败时振动如何停止

- 振动模块**自身**每路独立 30 s 超时，由 `vibration_task()` 在 loop 中检测并强制关闭；
- **不依赖** Workflow 执行停止步骤 ⇒ Workflow 中途失败/中断时仍能停止；
- Workflow 的 Timer 等待**不能替代**该保护（§11.2 已明确区分）。

## E. Workflow 业务流程（出粮）

| # | 步骤 | 类型 |
|---|---|---|
| 1 | 接收触发（人工命令 / 定时触发） | Trigger |
| 2 | 启动**储粮舱**振动马达 | Action `VIBRATION_START(motor=1, duration_ms)` |
| 3 | 等待预设时间 | **Timer Trigger**（非 Action） |
| 4 | 启动步进 120° 出粮旋转 | Action `STEPPER_DISPENSE_ROTATE` |
| 5 | 旋转期间振动继续 | （无新步骤；由步骤 2 的 duration 覆盖） |
| 6 | 旋转成功后继续等待 | **Timer Trigger** |
| 7 | 停止本次振动输出 | Action `VIBRATION_STOP(motor=…)` |
| 8 | 全部成功 ⇒ Workflow 成功 | 引擎既有语义 |

- **并发**：振动与步进是**独立 Action 实例**，可同时 RUNNING；
  步进脉冲由硬件外设产生，振动由 `millis()` 判定，无共享阻塞资源；
- **失败**：任一步骤失败 ⇒ 后续依赖步骤不执行；失败原因随 Action 结果上报；
  **不假定**步骤 7 一定执行 ⇒ 依赖振动自身 30 s 超时兜底；
- 优先使用 Workflow 引擎**既有**取消/失败机制，不发明全局清理系统。
