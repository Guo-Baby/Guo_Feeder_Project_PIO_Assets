## 6. 索引决策：`ix_lh_device_level_ts` —— **维持不新增**

### 6.1 证据

| # | 证据 | 结果 |
|---|---|---|
| 1 | 现有索引集合 | `log_history` **恰好 2 个**（`ix_lh_device_ts` · `ux_lh_dedup`）· `telemetry_history` **3 个** ⇒ 与 `WP2 §5` 冻结集合**逐字一致** |
| 2 | **级别过滤查询的执行计划** | **`SEARCH log_history USING INDEX ix_lh_device_ts (device_id=? AND ts>?)`** ⇒ **`level` 只作残留过滤，访问路径不变** |
| 3 | `WARN+` 选择性 | **11.8%**（16/136）⇒ **选择性低** |
| 4 | 单位窗口的过滤代价 | 1 天窗口 ≈ **57 行**；**180 天窗口 ≈ 10,260 行**（扫描后返回 ≈1,200 行） |
| 5 | **消费者查询** | **不存在** —— P4（Web UI）未开工；Worker 无 `level` 过滤端点 |
| 6 | 冻结决策 | `H-WP3-10` = **`no additional index`**；`WP2 §5.2 R2` = **暂缓（待 WP-6）** |

### 6.2 决策

> **`DEFER / NOT ADDED`（维持不新增）**

**理由（按权重）**：

1. **无消费者** ⇒ 任何索引都是"为不存在的查询付费"；索引会**增加每次写入的行写额度**（当前写入倍率已达 `5.24×`，原因未明，**不宜再加剧**）。
