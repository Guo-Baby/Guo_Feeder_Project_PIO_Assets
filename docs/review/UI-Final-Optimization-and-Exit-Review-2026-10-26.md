## 3. 配置版本机制的调查结论与缓存策略（§4.2 / §4.3）

### 3.1 调查结论（**逐跳有据**）

| 跳 | 位置 | 事实 |
|---|---|---|
| 固件产生 | `config_manager.cpp:2357` `out["versions"]`；`config_manager.h:157` `uint8_t version; // 模块配置版本（0~255 循环，仅用于判断新旧）` | **per-module** 的 uint8 计数器 |
| 固件持久化 | `config_manager.h:82` `#define CONFIG_VERSION_FILE "/config/version.json"`；`config_manager.cpp:653-680` 读、`:685-726` 写 | 存在 **Flash（LittleFS）** |
| 版本 +1 的**唯一**位置 | `config_manager.cpp:527` `m->version++;`（在 `save_module` 内） | ⇒ **只有 `config_save`（落盘）才 +1** |
| RAM 写入 | `config_manager.cpp:1726`（`exec_set_field` → `set_begin`）只置 `m->dirty = true` | ⇒ **`config_set` 不改版本** |
| 回滚 | `config_manager.cpp:805-824` | 版本**可能变小**（回到 version.json 里的可信值） |
| 边界 | `config_manager.h:157` 注释 + `config_manager.cpp:710-713` | uint8 回绕 255→**0**，而 **0 的语义是"未知"**且 `save_version_file` **跳过 0** ⇒ 该模块的新版本**不落盘** |
| 链路 | 前端 `gf-app.js:5037` ← 固件回帧**顶层**的 `data`/`versions`（`command_manager.cpp:3905-3927` + `cloud_manager.cpp:1154-1179`） | Worker **完全不理解** `versions`（`grep versions guo-feeder-api/src/` 零命中）⇒ 纯透传 |

### 3.2 结论：**版本号不能单独当"缓存里的配置值仍然有效"的判据**

五条硬反例：① RAM 写入不 +1（改完再读版本不变，值却变了）② `0` 是"未知"不是"版本 0" ③ uint8 回绕非单调 ④ 回滚让版本变小 ⑤ 模块级粒度 ⇒ 改一个键会 bump 整个模块（安全方向的过度失效，反向不成立）。

### 3.3 本轮采用的缓存策略（**不依赖固件改动**）

| 项 | 设计 |
|---|---|
| 缓存粒度 | 每设备 + 全量（`config_all`），localStorage 键 `gf_cache_<deviceId>_config_all` ⇒ 切设备天然隔离 |
| 有效性判定 | **四条件同时成立**才用缓存：① TTL 未到（`CONFIG_CACHE_TTL_SEC = 60`）② 本地**无**该模块的待落盘 RAM 改动 ③ 本会话无写/落盘/重启/版本冲突（这些都主动失效）④ 设备 ID 一致 |
| 版本的角色 | **辅助信号**：重新读到时若某模块版本变了 ⇒ 说明缓存期内设备侧**保存过**改动（可能来自另一客户端）⇒ 该模块需重新确认 |
| 主动失效 | 补上了**一直缺失**的 `family === "config"` 分支：`config_set` ⇒ 精确失效被改的那个模块；`config_save`/`config_restart` ⇒ 全清；重启族 ⇒ `invalidateAll` |
| 读取策略 | 进入配置区**自动读一次**（缓存命中则不发命令）；`config_query` 一次全量（1 条命令），**未**退回到"每模块一条"（那才是性能主因） |
| 固件按模块读 | 固件**已支持**（`command_manager.cpp:3138` `config_cmd_enqueue_query_module`），本轮**未**使用（避免 8 次往返），**无需任何固件改动** |
| 失败处理 | 失败**不写缓存**（不把失败当"没有变化"缓存住）；界面显示"读取失败"与"尚未读取"两种不同状态 |

**验收**：单测 **O-7i/O-7j/O-7k/O-7l**（失效分支 / TTL / 按设备隔离 / 版本只作辅助信号）· runtime **T-5-3**（自动读一次，1~3 条）· **T-8-4**（页面遍历期间 ≤2 条，不每页都读）。

门禁的**实际安全行为**（服务端 `validateConfigParams` / `configWriteAllowed` 三级 / 审计 / 无故障注入入口）仍在源码层保留，其**生产真机行为**归为 ④ 类「用户人工验收待完成」（§9.5）。
