## 1. 交付内容

### A3 · 指定步数出粮（`STEPPER_ROTATE_STEPS`）

固件动作早已存在（用户以为没支持），本轮**只做 UI 暴露**，零固件改动。

| 项    | 实现                                                                                       |
| ---- | ---------------------------------------------------------------------------------------- |
| 输入   | 脉冲数（数字框）+ 方向（出粮向/反向，来自目录枚举与中文标签）                                                         |
| 范围来源 | **能力目录** `STEPPER_ROTATE_STEPS.params[pulses]`（min 1 / max 6400）；目录缺失时保守按 1–6400 并在提示里说明 |
| 校验   | 必填 / 纯正整数（**不做四舍五入**）/ 目录范围；任一不过 ⇒ **本地拦截、零发布**（浏览器实测断言）                                 |
| 二次确认 | 明说三件事：脉冲数与方向、**设备端还会按自身 max_pulses 再钳位**、该动作未真机验证（DRV8825 损坏）                            |
| 落帧   | `family=action` + `params.pulses` / `params.direction`（浏览器实测逐字断言载荷）                      |

### A7 · System State 全量只读面板

| 项    | 实现                                                                                                                                               |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 键表   | **逐字对照固件** `src/services/system_state.cpp` 的 `state_map`：29 键 − 2 个 `readable=false`（`time_valid`/`weight_error`）= **27 键**，分 4 组（执行器/称重/温湿度/连接） |
| 取值分层 | ①重量/温度/湿度 ← **遥测缓存**（零往返，标注来源「遥测缓存」）；②常用 8 键 ← 按需查询；③全量 27 键 ← 二次确认后查询                                                                           |
| 性能   | 逐键分批并发（每批 4）+ 代际守卫（换设备/离页时旧响应不得回写）                                                                                                               |
| 诚实性  | 「未查询」/「查询中…」/「未取到（设备未回该键）」/「设备未提供（invalid）」/「遥测缓存」各有明示，**不猜不伪装**                                                                                 |
| 固件约束 | 固件 `system_state_query(key)` 是**单键查询**，无「一次读全量」命令 ⇒ 面板明确告知「越全越慢」，不做假全量                                                                           |

### A5 · 设备别名

| 项   | 实现                                                           |
| --- | ------------------------------------------------------------ |
| 存储  | `localStorage` 键 `gf.alias_<deviceId>`（**按设备隔离**，绝不串号）；零后端改动 |
| 生效面 | 顶部设备条（别名 + 原 device id 同时显示）、设备页「设备别名」区                      |
| 清洗  | 去控制字符 / 去首尾空白 / 限长 24 字；空 ⇒ 恢复默认（删键）                         |

### 顺带修复

- **固件压缩形态兼容**：设备回帧的 `key` 被压缩到 **`o`**（`value` 原样保留）⇒ 真实 state 回帧是 `{s,c,i,o,value}`。面板解析已同时认 `key` 与 `o`（否则上真机必然取不到值）。
- `gf-mqtt` 连接失败补 `console.warn` 诊断（直连失败时浏览器控制台可自查原因，不再只有「直连下发失败」一句）。

## 4. 使用说明（给用户）

- **指定步数出粮**：控制页 →「出粮（步进）」→ 填脉冲数（1–6400）→ 选方向 →「按指定脉冲出粮…」→ 二次确认后下发。
- **系统状态**：设备页 →「系统状态」→ 默认显示重量/温度/湿度（遥测缓存，标注来源）；点「刷新常用状态」查 8 个常用键；点「查询全部」查 27 键（较慢，会逐键往返）。
- **设备别名**：设备页 →「设备别名」→ 输入名字保存；顶部条会同时显示别名与原 device id；「恢复默认」删掉别名。

## 6. 已知限制

1. **System State 是逐键查询**（固件限制）：27 键全查 ≈ 7 批 × 设备往返；已在 UI 明示耗时并提供常用集。
2. **别名只在本机浏览器**（localStorage）：换浏览器/换设备看不到；跨端同步需后端表 + 鉴权（P1/P2 一起做更合适）。
3. **步进动作仍未真机验证**（DRV8825 损坏）：面板与确认文案都保留该警示，不因 UI 暴露而淡化风险。
4. 直连通道的既有限制（无云端审计、信任面在浏览器包、多标签页软上限、隐藏 60s 断连）见阶段四报告 §8。
