### P3-2 upsert 降频实现（视 P3-1 结论）

- STOP：任何回归失败 ⇒ 回滚，不降标准。

### P3-3 唯一 ID 与业务去重（**设计阶段**）
- 用户提议"时间戳 + 类型"组合 ID。必须分别解决：① 记录 ID 唯一/排序；② 日志重复上传识别去重。
- 候选比较（初判，须实测验证）：
  | 方案 | 唯一性 | 单调性 | 风险 |
  |---|---|---|---|
  | `AUTOINCREMENT id`（现状） | 强（DB 保证） | 强 | 单库单写者，跨库迁移需重建 |
  | `(boot_seq, seq)`（现状去重键） | 强（唯一索引） | 强（设备语义） | 跨设备需带 device_id |
  | 毫秒时间戳 + 设备/类型前缀 | **弱**（同 ms 并发、时钟回拨） | 弱 | 多标签/多设备时钟偏差；**不能替代主键** |
  | 时间戳 + 设备内单调计数 | 中 | 强 | 需设备侧协同（固件改动） |
- 结论（初步）：**时间戳组合不能满足"严格唯一+单调"**，只能作为"可读排序辅助列"；业务去重继续依赖 `ux_lh_dedup(device_id,boot_seq,seq)`。
- **STOP**：若要改去重策略 ⇒ 单独方案 + 测试矩阵 + 用户批准，本阶段不动。

### P3-4 重复错误日志降噪
- 设备侧渐进降频（首次立即、同类重复按 1/2/4/8…倍间隔、状态变化即重置、恢复事件必发、不同类型隔离、重启后从首条重来）。
- 与"配置层关闭模块"分列：配置关闭 = 立即止血但丢失诊断；固件降噪 = 保留诊断、需烧录。
- 验收（若实施）：同错误 1 小时写入 ≤ 6 条；恢复事件必现；首次错误不延迟。
- **STOP**：若降噪导致"持续故障不可见" ⇒ 改为"每 N 分钟一条摘要"而非纯丢弃。

### P3-5 记录数量估算模型
- 区分：`rowsRead`（扫描）/`rowsWritten`（含索引项）/**真实记录数**（`COUNT(*)` 或 `MAX(id)`）。
- 规则（可验证）：
  - `INSERT OR IGNORE`：写入行数 ≈ 1 + 索引数；读 = 唯一索引探测；**记录增量 ≤ 写入行数**
  - UPSERT：`ON CONFLICT DO UPDATE` 每次都算 1 行写（即使值未变）⇒ **不能用写入行数推记录增量**
  - DELETE：写入行数 = 删除行数 + 索引项
  - 记录数日变化 = `MAX(id)` 增量（app 侧无删除时）或 `COUNT(*)` 前后差（有保留策略时）
- 产出：`docs/` 说明 + 脚本参数（用 `?counts=1` 或 `MAX(id)` 采样，**限频**）。

### 12.3 其余修正

1. **Q2（snapshot COUNT）不能被索引改善**：`COUNT(*)` 必须遍历该设备全部索引项，`EXPLAIN` 前后都是 covering index ⇒ 唯一解是"不调用"（已落地）。原计划把它与索引收益合并表述，属误导，已拆开。
2. **我自己的验证脚本是第 5 大读消耗源**：`SELECT boot_seq, MAX(id) … GROUP BY boot_seq` 24 次执行 / **286,064 读（3.8%）** ⇒ 列入阶段二 Q2（脚本控频）必修项，改写为 `LIMIT 1` 取最新 boot_seq。
3. **帧端点不得去重**：`/api/read/history/frames` 现为 `ORDER BY id ASC LIMIT`，ACK/result/alert 全保留 —— 这是正确行为。P2-4 的去重键必须是 `frame.id`（或 `(cmd_id,direction,s)`），**禁止**按 `cmd_id` 单键去重。
4. **轮询需补代际守卫**：`runCommand` 现有固定 1.5s × 最长 75s（最多 50 次），且**页面切换不取消**、无 `visibilitychange` 检查、无代际守卫 ⇒ P2-4 必须补齐这三项。
5. **迁移执行粒度未验证**：D1 对文件内多语句是否同事务，本轮未验证 ⇒ 部署时**逐条执行 + 逐条校验**（`CREATE INDEX IF NOT EXISTS` 幂等，重跑安全）。
