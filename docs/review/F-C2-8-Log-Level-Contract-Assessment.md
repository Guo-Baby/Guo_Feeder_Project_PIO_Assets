### A2 固件实际输出（沿真实编码路径）

**编码路径（逐层）**：

```
LogRecord.level (uint8_t)                       src/log/log_events.h L458
   │
   ├─ enum LogLevel = DEBUG 0 / INFO 1 / WARN 2 / ERROR 3 / CRITICAL 4   L28-37
   │
   └─► cloud_build_envelope(n=1)                 log_manager.cpp L2267-2311
          rec = s_cloud_batch[0]                 L2275
          └─► log_envelope_encode_record(rec, …) L2305-2310
                 └─► log_envelope_encode_cbor(…, rec.level, …)   log_envelope.cpp L295
                        └─► jo_str(o, "\"level\":");             L255
                            jo_u32(o, (uint32_t)level);          L256
```

| 核实项 | 事实（读实现，非读函数名） | 判定 |
|---|---|---|
| **`jo_u32` 实际输出** | 实现为**十进制数字逐字符写出**（L142–163）：`if (v == 0u) jo_ch(o,'0')`，否则取模逐位写 `'0'+v%10`。**全程不写引号** ⇒ 产出 JSON **number**（如 `"level":3`） | ✅ **CONFIRMED** |
| **底层枚举 / 数值** | `LogLevel`：`DEBUG=0` · `INFO=1` · `WARN=2` · `ERROR=3` · `CRITICAL=4` | ✅ |
| **数值 ↔ 语义映射** | 上述 5 值映射（`log_events.h` L28–37） | ✅ |
| **是否存在 DEBUG/INFO** | ✅ **两者均存在**；且 `LOG_LEVEL_POLICY`：DEBUG `flash=0/cloud=0` · **INFO `flash=0/cloud=1`** | ✅ |
| **截断 / 默认值 / 越界** | **无截断、无默认值替换**：`level` 直接 `(uint32_t)` 强转写出（L256）⇒ 原值透传；`LogRecord.level` 为 `uint8_t`，越界值亦原样写出 | ✅ |
| **CBOR→JSON 过程是否改类型** | ❌ 不改 —— `payload_base64` 是 `log_cbor_encode_batch(1)` 的**原样 Base64**；信封标量 `level` 由 `rec.level` **单独**写出（两路独立） | ✅ |
| **实际 envelope vs 协议** | **与 `cloud_protocol.md` §8.2.1 的 `uint8` 声明一致**（number 形态） | ✅ |
| **是否存在等级字符串映射** | 固件内 `logt_level_name()`（`main.cpp` L807–817）返回 `"DEBUG"/"INFO"/"WARN"/"ERROR"/"CRITICAL"`，但**仅用于串口调试台 `logt`**，**不在 `/log` 信封路径上**（`cloud_build_envelope` 不引用它） | ✅ **不在链路上** |

> **★ 结论**：固件 `/log` 信封的 `level` **确定是 JSON number**（0..4），**且 INFO 会进入信封**。

### A3 Worker 实际校验（`history-ingest.js`）

| 核实项 | 事实 | 位置 |
|---|---|---|
| **是否只接受字符串 `level`** | ✅ **是**。`const level = asText(…); if (level === null \|\| !LOG_LEVELS.has(level)) return null;` —— `LOG_LEVELS = new Set(["WARN","ERROR","CRITICAL"])` | L49–50 · **L401–405** |
| **`asText` 对数字** | `if (typeof v !== "string") return null;` ⇒ **数字 ⇒ `null`** ⇒ 该记录 `rejected` | **L284–292** |
| **`asText` 对缺字段 / `null`** | 取值表达式 `rec.level !== undefined ? rec.level : env2.level`；两者皆 `undefined` ⇒ `asText(undefined)` = (`typeof undefined !== "string"`) ⇒ **`null`**；显式 `null` ⇒ `typeof null === "object"` ⇒ **`null`**。**一律拒收** | L401 · L284–292 |
| **记录级拒收是否仍返 200** | ✅ **是**。记录级失败只 `rejected++`（L152–165），HTTP 状态**恒为 200**；响应体 `{accepted, duplicate, rejected}` | **L184–191** |
| **批次级 vs 记录级** | **记录级**：`for` 循环逐条归一化，坏条只累加 `rejected`，**好条仍写入** ⇒ **部分成功**（`accepted` 与 `rejected` 可同时非 0） | L149–165 |
| **`INFO` 是否被接受** | ❌ **不接受** —— 既因**类型**（若为数字），也因 `LOG_LEVELS` **不含 `"INFO"`**。代码注释明写：「**不含 INFO（INFO 不入库由上游保证）**」 | L49 · L402–405 |
| **D1 保存的原值 / 规范化值** | 保存 = **Worker 校验通过的字符串原值**（`env` 值不参与转换）⇒ **存的是字符串等级本身**（若入口是数字则根本到不了 persist） | L443 · L472–478 |
| **是否有其他入口 / 兼容分支** | ❌ **无**。`level` 校验仅此一处；`grep` 全仓（排除 `.wrangler/tmp` 构建产物）只有 `history-ingest.js` 两处引用；**不存在数字兼容分支** | — |
| **非法等级 / 类型错误 / 缺字段是否区别处理** | ❌ **不区分** —— 三者**同归** `return null` ⇒ `rejected++`，**无差异化错误码**（响应体只有一个总 `rejected` 计数） | L401–405 · L184–191 |
| **上游假设是否成立** | 🔴 **不成立** —— 注释称「INFO 不入库由上游保证」，但**上游（固件 `LOG_LEVEL_POLICY`）INFO → `cloud=1`，确实上传** | P-4 L64–71 |

> **★ 结论**：Worker **只接受 `{WARN, ERROR, CRITICAL}` 字符串**；**数字一律拒收**；**INFO 双重不被接受**；**拒收仍返 200**（`rejected` 计数表达）。
