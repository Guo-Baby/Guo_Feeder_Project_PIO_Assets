## 一句话结论

功能级真机缺口只剩 **步进**（DRV8825 损坏）与 **振动定时停止**；
UI 侧的真正阻塞是 **命令通路的三个全局缺口**：

1. **`/api/command` 完全匿名** —— 任何人知道 device_id 就能开阀（`10` §1.2 G-2）
2. **Worker `cloud_api` 分支不校验 Bearer** —— 绕过 Pages 直连（G-3）
3. **没有任何端点能读设备回帧** —— 控制界面无法诚实反馈（G-1）

★ 三者**必须同时修**，只修一侧等于没修。

## 五个最容易踩的坑（已写进文档，提前记住）

1. **`workflow_stop()` 不是停机** —— 只清状态，阀门照样出水。强停必须"停账本 + 停硬件 + 读回核实"三层。
2. **`log_history.message` 100% NULL** —— 看板日志列空不是加载失败；内容在 `payload` 的 base64 CBOR 里。
3. **`registry` 只给"名字↔数字"** —— 没有参数范围/默认值/单位；表单约束只能来自云端目录。
4. **"30 秒内重复 cmd_id" = 完全没回应** —— 与设备离线不可区分；重试必须靠"复用同一 id + 人判断"。
5. **`system reboot` 不拒绝、只等待** —— 有 Critical Operation 时会无限挂着；UI 不能用它当"强制重启"。
