## 2. 统一实施计划

### 2.1 任务卡（每项含审计 §编号）

**P0-1 · 会话 touch 节流（= Q1'a）**
- 现状：每 API 请求 1 写（无节流）[代码]。价值：**写消耗 -95%+**（估算）。
- 文件：`guo-feeder-api/src/ui-session.js`（SELECT 增取 last_seen_at；>60s 才 UPDATE）+ 测试。
- 请求/D1：不增 HTTP；写大降。安全：零（touch 纯观测，源码自证）。回滚：单参数开关。
- 非目标：不改鉴权语义、不改 fail-closed。完成条件：单测（节流窗口/撤销立即生效）+ 生产一次登录走查。
- 无需用户决策（零安全代价），但按纪律列为待批。

**P0-2 · metrics 全表 COUNT 治理（R15）**
- 方案：设备页诊断改 `MAX(id)` 近似 + admin/metrics 保留给运维（或 60s isolate 缓存）。读消耗随表规模归零（估算：5 万行表每次省 ~5 万行读）。
- 文件：read-api.js（MAX(id) 版端点或参数）+ gf-app.js + 测试。需用户选择口径（精确 COUNT vs 近似 MAX）→ **❓ 决策点**。

**P1-1 · 命令轮询退避（= Q1'b）**
- 1.5s 恒定 → 1.5s×3 后 2s/3s/4s 递增；75s 上限、terminal/timeout 终止条件不变 [现行为：代码]。
- 收益（估算）：慢命令请求数 -40~60%。文件：gf-app.js runCommand。无安全影响。

**P1-2 · B3 配置全量单查**
- 7×config_query(keys_only) → 1×config_query(无 module)；缓存失效逻辑不变。
- 收益：首次/失效后 7 条命令 → 1 条（≈ -86% 命令成本，估算）。依赖：无（固件已支持）。

**P1-3 · snapshot COUNT 轻量化**
- per-device 3×COUNT(*) → MAX(id) 近似或复用 metrics 改造口径。❓ 同 P0-2 口径决策。

**P2-1 · 快捷操作可配置（S3-04）**：localStorage 布局 + 目录选器；安全四要素（开阀/关阀/急停/解除）常驻。0 D1 影响。
**P2-2 · 首页排序/持久化/恢复默认（S3-05）**：同 localStorage 方案。0 D1 影响。
**P2-3 · 指定脉冲出粮（S3-09）**：输入框 + 上下限取 `config_query stepper max_pulses`（B3 后顺带）；设备端再钳位 [代码]。
**P2-4 · 设备别名（S3-01）**：纯前端 localStorage（不进 D1；多设备共享留 P1 一并设计）。
**P2-5 · P3 System State 面板**：设备页新增状态网格，`query_state` 逐键按需点查（不做自动全查——配额纪律）；29 键清单见审计。
**P2-6 · A6/A7 震动/出粮状态暴露**：并入 P2-5 面板（stepper_busy/vibration_active 等键）。
**P2-7 · P5 审计筛选扩展**：family/时间范围参数（端点已有 WHERE 骨架 [代码]）。

**P3-1 · P4/B2 EMQX 在线状态**：Worker `GET /api/presence/emqx/:device`（emqx-admin 加 clients 查询 + 30s isolate 缓存限频）；UI 首页/设备页显示权威在线口径。需 ❓ 决策（新增端点涉及 EMQX API 调用配额）。
**P3-2 · P1 多设备**：设备列表（来源：device 表只读端点）+ 切换 + 缓存全键隔离验证（gf-cache 已按 device_id 键控 [代码]）。❓ 决策（范围较大）。
**P3-3 · P2 模块配置 UI 化**：**单独设计文档先行**（协议见《MQTT-Command-Reference.md》§8：config_set→config_save→restart→复核四步；CFG-ROLLBACK 铁律；GPIO 警示；"命令接受≠生效"展示）。**必须等用户审阅设计后再动工**。

**P4-1 · Q2 脚本控频**：verify_*.py 预算制（单次运行 ≤N 请求、间隔 ≥5s、失败不重试）。
**P4-2 · B1 生产验收补跑**（配额恢复后）：走查缓存命中/失效/跨设备隔离，生产预算 ≤50 请求。
**P4-3 · Q3 设备侧写消耗**：遥测/日志/ACK 固有写。❓ 决策是否立固件议题。

## 3. 验收指标设计

**本地自动化（每次回归）**：
1. 每页面首载/复访请求数断言（现有 T-15 缓存行为测试扩展：复访 = 0 命令请求）。
2. touch 节流：单测模拟 60s 窗口内 N 请求 ⇒ UPDATE ≤1；撤销后 0 放行。
3. 轮询退避：慢命令模拟 ⇒ 轮询次数 ≤ 上限曲线；terminal 即停。
4. 跨设备隔离：改 device_id ⇒ 缓存全 miss（现有键控断言扩展）。
5. 幂等：同 cmd_id 重发 ⇒ 30s 内静默丢弃（固件语义，云端 audit 不重复计）。

**生产验收（预算制，配额恢复后执行）**：
- 预算：单轮走查 ≤50 HTTP 请求、≤10 命令、≤30s 总轮询窗；禁秒级轮询脚本。
- 指标：① 每典型操作 D1 读/写实测（Worker 观测或 wrangler analytics）；② 会话成本 = 请求/2（Pages→Worker 双跳）；③ 缓存命中率（UI 埋点日志）；④ 撤销后 ≤1 请求内 401（fail-closed 实测）；⑤ 月度配额余量核对（Cloudflare dashboard）。
- 可观测性（低成本）：UI 侧本地计数上报（不发 D1）；Worker console.log 结构化计数（日志免费层）。
