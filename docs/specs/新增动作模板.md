# 新增动作模块开发模板（应用模块 + 底层驱动模块）

> 适用场景：在现有 ESP32 Arduino 固件中新增"应用模块 + 底层驱动模块"（如电机、阀门、称重、加热等）。
> 本文模板严格基于当前 `workflow.h` / `event_manager.h` / `system_state.h` 真实接口，**不修改 Workflow 框架**。

---

## 0. 模块边界（重点说明）

一个动作模块（以 `xxx_module` 为例）只负责三件事：

1. **初始化硬件**并注册自己的 Action / Trigger 描述符；
2. **执行动作**：通过 `WorkflowActionDescriptor.start/poll` 完成具体硬件操作，并更新自身运行状态（`action->result` / `action->runtime`）；
3. **同步状态**：硬件状态变化时写 `SystemState`，必要时发布 `Event`。

模块**不负责**、**不实现**：

- CommandManager 逻辑（不调用 `command_manager_*` 接口、不生成命令结果 JSON）；
- 命令回调（不主动调用 `action->callback`；命令级回调由 CommandManager 契约与 Workflow 框架管理）；
- Workflow 生命周期 / 步骤调度（由 `workflow_task()` 驱动）；
- 修改 workflow / event_manager / system_state 框架代码。

同一份 Action 描述符天然支持两种调用方式，模块无需感知差异：

- **Workflow 步骤调用**：workflow 配置 JSON 中 `{"type":"action","id":"XXX_ACTION"}`，由 `workflow_task()` 驱动；
- **Command 临时 Action 调用**：CommandManager 经 `workflow_enqueue_action(id, payload, ...)` 执行，模块仍只被调用 `start/poll`。

文件结构：

```
src/xxx_module.h      // 对外接口（init/task/硬件操作）
src/xxx_module.cpp    // 实现：descriptor + reset/start/poll + 事件 + 状态
```

## 1. Workflow Action 注册模板

### 1.1 参数定义（`WorkflowParam[]`，静态存储）

参数描述用于 UI / 配置界面；实例运行时实际值在 `WorkflowActionInstance.params[]` 中。

```cpp
// 参数类型: PARAM_INT / PARAM_FLOAT / PARAM_BOOL / PARAM_STRING
static WorkflowParam xxx_params[] = {
    {"duration_ms", PARAM_INT,    "ms", "动作持续时间（毫秒）"},
    {"level",       PARAM_INT,    "",   "目标档位 0-100"},
    {"enable",      PARAM_BOOL,   "",   "是否启用"},
    {"mode",        PARAM_STRING, "",   "模式: fast/slow"},
};
```

### 1.2 Descriptor 定义（`WorkflowActionDescriptor`，静态存储）

```cpp
// 前向声明
static void xxx_action_reset(WorkflowActionInstance *action);
static void xxx_action_start(WorkflowActionInstance *action);
static void xxx_action_poll(WorkflowActionInstance *action);

static WorkflowActionDescriptor xxx_action_desc = {
    .id          = "XXX_ACTION",          // 全局唯一，Workflow JSON / 命令中引用
    .name        = "动作显示名",
    .module      = "xxx",                 // 所属模块名
    .description = "动作描述",
    .params      = xxx_params,
    .param_count = sizeof(xxx_params) / sizeof(xxx_params[0]),
    .reset       = xxx_action_reset,      // 初始化运行状态
    .start       = xxx_action_start,      // 第一次进入 step 时调用
    .poll        = xxx_action_poll        // workflow_task 周期调用（非阻塞）
};
```

### 1.3 reset（每次执行前复位）

```cpp
static void xxx_action_reset(WorkflowActionInstance *action)
{
    if(action == nullptr)
        return;
    action->result  = ACTION_IDLE;
    action->running = false;
    action->runtime = nullptr;   // 释放模块私有上下文（如有）
}
```

### 1.4 start（启动动作）

```cpp
static void xxx_action_start(WorkflowActionInstance *action)
{
    if(action == nullptr)
        return;
    // 读取参数（见 5.3 参数读取助手）
    int duration = action_get_int_param(action, "duration_ms", 1000);
    // 执行硬件动作...
    // 规则：start 结束后 result 仍为 ACTION_IDLE 时，引擎会自动置为 ACTION_RUNNING。
    // 即时完成：action->result = ACTION_SUCCESS / ACTION_FAILED;
    // 异步执行：action->result = ACTION_RUNNING;（并初始化 action->runtime）
}
```

### 1.5 poll（异步轮询，可选）

```cpp
static void xxx_action_poll(WorkflowActionInstance *action)
{
    if(action == nullptr)
        return;
    // 未 start 而直接 poll（异常路径）：直接失败
    if(action->result == ACTION_IDLE) {
        action->result = ACTION_FAILED;
        return;
    }
    // 检查硬件/时间进度...
    // 完成: action->result = ACTION_SUCCESS;  引擎推进下一步
    // 失败: action->result = ACTION_FAILED;   引擎置 WORKFLOW_ERROR
    // 未完成: action->result = ACTION_RUNNING; 继续等待
}
```

### 1.6 注册（在模块 init 中）

```cpp
bool ok = workflow_register_action(&xxx_action_desc);
if(!ok) {
    // 注册失败：id 重复 或 Action 注册表已满（WORKFLOW_MAX_ACTION = 32）
    Serial.println("[Xxx] Action register failed");
}
```

## 2. Workflow Trigger 注册模板（需要主动触发时）

> 内置 Trigger 已注册：`timer`（type=once/daily/weekly，参数 hour/minute/year/month/day/day_of_week）、`delay`（参数 seconds）。多数模块无需自定义 Trigger；仅在需要"条件轮询触发"时使用本模板。

### 2.1 Descriptor 定义（`WorkflowTriggerDescriptor`）

```cpp
static WorkflowParam xxx_trigger_params[] = {
    {"threshold", PARAM_FLOAT, "", "触发阈值"},
};

static void xxx_trigger_reset(WorkflowTriggerInstance *trigger);
static void xxx_trigger_start(WorkflowTriggerInstance *trigger);
static void xxx_trigger_poll(WorkflowTriggerInstance *trigger);

static WorkflowTriggerDescriptor xxx_trigger_desc = {
    .id          = "xxx_condition",       // 全局唯一
    .name        = "条件触发",
    .module      = "xxx",
    .description = "当条件满足时触发",
    .params      = xxx_trigger_params,
    .param_count = sizeof(xxx_trigger_params) / sizeof(xxx_trigger_params[0]),
    .reset       = xxx_trigger_reset,
    .start       = xxx_trigger_start,
    .poll        = xxx_trigger_poll
};
```

### 2.2 reset / start / poll

```cpp
static void xxx_trigger_reset(WorkflowTriggerInstance *trigger)
{
    if(trigger == nullptr)
        return;
    trigger->state   = TRIGGER_IDLE;
    trigger->running = false;
}

static void xxx_trigger_start(WorkflowTriggerInstance *trigger)
{
    if(trigger == nullptr)
        return;
    trigger->state   = TRIGGER_RUNNING;
    trigger->running = true;
    // 初始化轮询条件（可选：记录初始值）
}

static void xxx_trigger_poll(WorkflowTriggerInstance *trigger)
{
    if(trigger == nullptr)
        return;
    // 检查条件...
    if(条件满足) {
        trigger->state = TRIGGER_SUCCESS;   // 引擎推进下一步
        trigger->running = false;
    } else if(条件失败) {
        trigger->state = TRIGGER_FAILED;    // 引擎置 WORKFLOW_ERROR
        trigger->running = false;
    } else {
        trigger->state = TRIGGER_RUNNING;   // 继续等待
    }
}
```

### 2.3 注册

```cpp
bool ok = workflow_register_trigger(&xxx_trigger_desc);
if(!ok) {
    Serial.println("[Xxx] Trigger register failed");
}
```

### 2.4 事件型 Trigger 注意事项

- Workflow 支持以 `event_xxx` 开头的 Trigger id 响应 `EventManager` 事件，但当前框架宏 `WORKFLOW_EVENT_ENABLED = 0`（默认关闭事件触发）；启用需修改 workflow.h 宏并同步事件映射（见第 3 节）。
- 事件订阅与响应由 Workflow 框架统一完成，**模块不要自行订阅事件去启动 Workflow**。

## 3. EventManager 事件发布模板

### 3.1 事件定义位置（新增事件需改 2 处文件）

**（1）`src/services/event_manager.h` — `enum SystemEvent`：**

- 需要被 workflow 事件型 Trigger 响应的事件，放在 `EVENT_ERROR` **之前**；
- 纯通知/展示类事件，放在 `EVENT_ERROR` **之后**（如现有 `EVENT_VALVE_OPEN` 等）；
- `SYSTEM_EVENT_COUNT` 当前为**基于最后 EventId 的维护型计数宏**（现为 `(EVENT_VALVE_ERROR + 1)` = 17）。
  新增 `SystemEvent` 时必须同步检查 enum 与 string registry。

```cpp
enum SystemEvent
{
    // ... 现有事件 ...
    EVENT_ERROR,          // 分隔点：上方可被 workflow trigger 响应
    EVENT_XXX_CHANGED,    // 新增：模块状态变化
    EVENT_XXX_ERROR       // 新增：模块错误
};
```

**（2）`src/services/event_manager.cpp` — 两个字符串映射表必须同步添加：**

- `SystemEvent event_from_string(const String &str)` 中的 `event_names[]`；
- `String event_to_string(SystemEvent event)` 中的 `event_names[]`。

> ⚠️ 既有坑：`EVENT_CLOUD_COMMAND` 在映射表与 `valve.cpp` 中被引用，但枚举中缺失（既有编译问题）。新增事件务必"枚举 + 两个映射表"三处同步，避免复现此类问题。

### 3.2 发布标准写法

```cpp
// 状态变化类事件：建议 EVENT_POLICY_STATE（同事件新状态覆盖旧状态，防堆积）
event_push(
    EVENT_XXX_CHANGED,        // 事件枚举
    "value=123",              // data：可选负载（见 3.3）
    "xxx",                    // source：模块名
    EVENT_PRIORITY_NORMAL,    // LOW=0 / NORMAL=1 / HIGH=2 / CRITICAL=3
    EVENT_POLICY_STATE,       // NORMAL / DEDUP / STATE / FORCE
    0                         // expire：0 = 永不过期
);

// 一次性通知类事件：EVENT_POLICY_NORMAL 或 DEDUP
event_push(EVENT_XXX_ERROR, "code=1", "xxx");
```

发布时机建议：硬件状态实际变化后立即发布（不在 task 中重复发布相同状态）；错误发生时发布错误事件。

### 3.3 payload 设计

- `EventMessage.data` 是 `String`，仅适合轻量数据：`"key=value"`、`"k1=v1;k2=v2"` 或小型 JSON 字符串；
- 订阅方自行解析；不要把大结构/二进制塞入 data；
- 复杂数据走 `SystemState` 存储 + 事件仅作"变化通知"。

## 4. SystemState 维护模板

### 4.1 状态定义位置

**（1）`src/services/system_state.h` — `enum SystemStateKey`（在 `STATE_MAX` 之前新增）：**

```cpp
enum SystemStateKey
{
    // ... 现有状态 ...
    STATE_XXX_VALUE,      // 新增：模块当前值
    STATE_XXX_ERROR,      // 新增：模块错误码
    STATE_MAX             // 自动维护数量
};
```

**（2）`src/services/system_state.cpp` — `state_map` 映射表**（按头文件注释要求同步维护；`state_get_field_count()` / `state_get_field_name()` 自动更新）。

### 4.2 写入（谁产生谁写）

```cpp
state_set_int(STATE_XXX_VALUE, value);        // 整数
state_set_float(STATE_XXX_VALUE, 1.5f);       // 浮点
state_set_bool(STATE_XXX_VALUE, true);        // 布尔
state_set_long(STATE_XXX_VALUE, 123L);        // 长整型
state_set_string(STATE_XXX_VALUE, "text");    // 字符串
```

### 4.3 读取

```cpp
int   v  = state_get_int(STATE_XXX_VALUE);
bool  ok = state_is_valid(STATE_XXX_VALUE);
```

### 4.4 硬件状态与 SystemState 同步方式

1. **init 完成后**立即写一次初始状态；
2. **每次硬件操作生效后**同步写（如阀门 open/close 后写 `STATE_VALVE_STATUS`）；
3. **task 周期轮询**硬件时更新（如称重模块每采样周期写 `STATE_WEIGHT_VALUE`）；
4. CommandManager 查询走统一接口 `system_state_query(key, output)`，模块无需感知。

## 5. Action 实现模板

### 5.1 即时完成 Action（同步硬件操作）

适用：GPIO 开关、瞬时命令类（如阀门、LED）。

```cpp
static void xxx_set_on_start(WorkflowActionInstance *action)
{
    if(action == nullptr)
        return;
    // 直接执行并立刻给出结果
    if(xxx_hardware_set_on()) {
        action->result = ACTION_SUCCESS;
    } else {
        action->result = ACTION_FAILED;
    }
    // poll 会兜底：IDLE 不会残留
}

static void xxx_set_on_poll(WorkflowActionInstance *action)
{
    if(action == nullptr)
        return;
    if(action->result == ACTION_IDLE)
        action->result = ACTION_FAILED;
}
```

### 5.2 异步完成 Action（长时间操作）

适用：电机移动、出料、加热、封口等需要持续时间的动作。

```cpp
// 模块私有运行上下文（静态池，由模块自己管理分配/释放）
struct XxxRunCtx
{
    bool used;
    unsigned long start_ms;
    unsigned long duration_ms;
};

static XxxRunCtx xxx_ctx_pool[8];

static XxxRunCtx *xxx_ctx_alloc()
{
    for(uint8_t i = 0; i < 8; i++) {
        if(!xxx_ctx_pool[i].used) {
            xxx_ctx_pool[i].used = true;
            return &xxx_ctx_pool[i];
        }
    }
    return nullptr;
}

static void xxx_ctx_free(XxxRunCtx *ctx)
{
    if(ctx != nullptr)
        ctx->used = false;
}

static void xxx_move_start(WorkflowActionInstance *action)
{
    if(action == nullptr)
        return;
    XxxRunCtx *ctx = xxx_ctx_alloc();
    if(ctx == nullptr) {
        action->result = ACTION_FAILED;
        return;
    }
    ctx->start_ms    = millis();
    ctx->duration_ms = (unsigned long)action_get_int_param(action, "duration_ms", 1000);
    action->runtime  = ctx;
    action->result   = ACTION_RUNNING;   // 显式置 RUNNING 开始异步执行
    xxx_hardware_start();                // 启动硬件
}

static void xxx_move_poll(WorkflowActionInstance *action)
{
    if(action == nullptr)
        return;
    XxxRunCtx *ctx = (XxxRunCtx *)action->runtime;
    if(ctx == nullptr) {
        action->result = ACTION_FAILED;
        return;
    }
    if(millis() - ctx->start_ms >= ctx->duration_ms) {
        xxx_hardware_stop();             // 硬件收尾
        action->result = ACTION_SUCCESS;
    } else {
        action->result = ACTION_RUNNING;
    }
}

static void xxx_move_reset(WorkflowActionInstance *action)
{
    if(action == nullptr)
        return;
    xxx_ctx_free((XxxRunCtx *)action->runtime);
    action->runtime = nullptr;
    action->result  = ACTION_IDLE;
    action->running = false;
}
```

### 5.3 参数读取助手（模块内常用）

```cpp
static int action_get_int_param(WorkflowActionInstance *action, const char *name, int def)
{
    for(uint8_t i = 0; i < action->param_count; i++) {
        if(action->params[i].name == name)
            return action->params[i].int_value;
    }
    return def;
}
```

> 参数来源：Workflow 配置 JSON 的 `steps[].params`，或 Command 临时 Action 的 payload（由 Workflow 在入队时解析为 `params[]`）。模块只需按参数名读取，不感知来源。

## 6. 完整示例模块 valve_module.cpp

> 综合示例：同步 Action × 2 + Event 发布 + SystemState 更新 + （可选）Trigger 注册注释。风格对齐现有 `valve.cpp`。

### valve_module.h

```cpp
#pragma once

// 初始化（main.cpp setup 中调用，须在 workflow_init() 之后）
void valve_module_init();

// 任务（main.cpp loop 中调用）：安全超时等
void valve_module_task();

// 对外硬件接口（调试 / 其他模块可调用）
bool valve_module_open();
bool valve_module_close();
bool valve_module_toggle();
bool valve_module_is_open();
int  valve_module_get_pin();
```

### valve_module.cpp

```cpp
#include <Arduino.h>
#include <driver/gpio.h>

#include "valve_module.h"
#include "workflow.h"
#include "event_manager.h"
#include "system_state.h"
#include "config_manager.h"

// =====================================================
// 硬件状态（模块私有）
// =====================================================
static int  valve_pin        = -1;
static int  active_level     = 1;
static bool current_state    = false;
static bool initialized      = false;

static unsigned long open_start_time = 0;
static const unsigned long SAFETY_TIMEOUT_MS = 300000UL;  // 安全超时

// =====================================================
// Action 参数（本示例无参数）
// =====================================================
static WorkflowParam valve_params[] = {
    // 如需参数: {"hold_ms", PARAM_INT, "ms", "保持时间"}
};

// =====================================================
// Action Descriptor（前向声明 + 定义）
// =====================================================
static void valve_action_reset(WorkflowActionInstance *action);
static void valve_open_start(WorkflowActionInstance *action);
static void valve_close_start(WorkflowActionInstance *action);
static void valve_action_poll(WorkflowActionInstance *action);

static WorkflowActionDescriptor valve_open_desc = {
    .id          = "VALVE_OPEN",
    .name        = "电磁阀开",
    .module      = "valve",
    .description = "打开电磁阀",
    .params      = valve_params,
    .param_count = 0,
    .reset       = valve_action_reset,
    .start       = valve_open_start,
    .poll        = valve_action_poll
};

static WorkflowActionDescriptor valve_close_desc = {
    .id          = "VALVE_CLOSE",
    .name        = "电磁阀关",
    .module      = "valve",
    .description = "关闭电磁阀",
    .params      = valve_params,
    .param_count = 0,
    .reset       = valve_action_reset,
    .start       = valve_close_start,
    .poll        = valve_action_poll
};

// =====================================================
// 内部函数：GPIO 控制 + 状态同步 + 事件发布
// =====================================================
static void valve_set_gpio(bool open)
{
    if(valve_pin < 0)
        return;
    if(open == current_state)
        return;

    int level = open ? active_level : (1 - active_level);
    gpio_set_level((gpio_num_t)valve_pin, level);
    current_state = open;

    // 硬件状态 → SystemState 同步
    state_set_bool(STATE_VALVE_STATUS, current_state);

    // 硬件状态变化 → Event 发布
    if(open) {
        event_push(EVENT_VALVE_OPEN, "", "valve", 0, EVENT_POLICY_STATE, 0);
        open_start_time = millis();
    } else {
        event_push(EVENT_VALVE_CLOSE, "", "valve", 0, EVENT_POLICY_STATE, 0);
        open_start_time = 0;
    }
}

// =====================================================
// Workflow Action 实现（即时完成）
// =====================================================
static void valve_action_reset(WorkflowActionInstance *action)
{
    if(action == nullptr)
        return;
    action->result  = ACTION_IDLE;
    action->running = false;
    action->runtime = nullptr;
}

static void valve_open_start(WorkflowActionInstance *action)
{
    if(action == nullptr)
        return;
    action->result = valve_module_open() ? ACTION_SUCCESS : ACTION_FAILED;
}

static void valve_close_start(WorkflowActionInstance *action)
{
    if(action == nullptr)
        return;
    action->result = valve_module_close() ? ACTION_SUCCESS : ACTION_FAILED;
}

static void valve_action_poll(WorkflowActionInstance *action)
{
    if(action == nullptr)
        return;
    if(action->result == ACTION_IDLE) {
        action->result = ACTION_FAILED;
    }
}

// （可选）Trigger 示例：非事件型条件触发，注册与否按需
// =====================================================

// =====================================================
// 初始化
// =====================================================
void valve_module_init()
{
    // 1. 读取配置（示例 key；实际以 config_manager 为准）
    valve_pin    = config_get_valve_gpio_pin();
    active_level = config_get_valve_active_level();
    bool enable  = config_get_valve_enable();
    if(!enable || valve_pin < 0) {
        Serial.println("[Valve] Disabled by config");
        return;
    }

    // 2. 配置 GPIO 并初始化为关闭
    gpio_config_t io_conf = {
        .pin_bit_mask = (1ULL << valve_pin),
        .mode = GPIO_MODE_OUTPUT,
        .pull_up_en = GPIO_PULLUP_DISABLE,
        .pull_down_en = GPIO_PULLDOWN_DISABLE,
        .intr_type = GPIO_INTR_DISABLE,
    };
    gpio_config(&io_conf);
    valve_module_close();

    // 3. 注册 Workflow Action
    workflow_register_action(&valve_open_desc);
    workflow_register_action(&valve_close_desc);

    // 4.（可选）注册 Trigger
    // workflow_register_trigger(&valve_trigger_desc);

    // 5. 初始状态同步
    state_set_bool(STATE_VALVE_STATUS, current_state);
    initialized = true;
    Serial.println("[Valve] Init OK");
}

// =====================================================
// 对外硬件接口
// =====================================================
bool valve_module_open()
{
    if(valve_pin < 0)
        return false;
    valve_set_gpio(true);
    return current_state;
}

bool valve_module_close()
{
    if(valve_pin < 0)
        return false;
    valve_set_gpio(false);
    return !current_state;
}

bool valve_module_toggle()
{
    if(valve_pin < 0)
        return false;
    bool target = !current_state;
    valve_set_gpio(target);
    return (current_state == target);
}

bool valve_module_is_open() { return current_state; }
int  valve_module_get_pin() { return valve_pin; }

// =====================================================
// 任务（安全超时检测）
// =====================================================
void valve_module_task()
{
    if(!initialized || valve_pin < 0)
        return;
    if(!current_state)
        return;
    if(millis() - open_start_time >= SAFETY_TIMEOUT_MS) {
        valve_module_close();
        event_push(EVENT_VALVE_ERROR, "Safety timeout", "valve", 0, EVENT_POLICY_STATE, 0);
    }
}
```

### 接入 main.cpp

```cpp
// setup()：在 workflow_init() 之后、加载 workflow.json 之前
valve_module_init();

// loop()
valve_module_task();
```
