# 自动猫咪饮水系统软件需求设计文档 V2.1

________________________________________
0. 项目概述
本项目目标是开发一个基于 ESP32 的智能猫咪自动饮水系统。
当前方案：
•	水箱储水
•	重力供水
•	电磁阀控制出水
•	HX711 + 称重传感器实时检测水箱重量
•	ESP32作为中央控制器
•	OLED显示运行状态
•	WiFi连接云端，实现远程控制和参数修改
核心目标：
根据重量变化精确控制每次出水量，并保证任何异常情况下不会持续漏水。

## 5. Log 日志模块

统一日志系统（**已实现**：P1 基础设施 + P2 逐模块接入；详见
`docs/specs/LogManager-Integration-Guide.md` 与 `docs/archive/log/LogManager-P2-Progress.md`）。

功能：

- 日志等级（**冻结 5 级**）：
  - DEBUG（不落盘、不上云，只计侧信道计数）
  - INFO
  - WARN
  - ERROR
  - CRITICAL

- 日志输出（三条通路，互相独立）：
  - 串口（调试）
  - MQTT 云端上报（**已实现**：独立 `guo_feeder/log` Topic + `log_ack` 下行回执）
  - 本地 Flash 段环（离线耐久层 / 重启后补发源，16 段 × 31 条 = 496 条）

设计：

- 内存 Ring Buffer（64 槽 × 128 B，PSRAM 优先）
- 避免业务代码大量 Serial 输出
- 支持 Config 控制日志等级（后续）
- **写入压力控制**（核心目标 = 降低 Flash 写入次数且不影响主循环性能）：
  - **Level Policy**：INFO 只上云、不落 Flash；WARN 及以上才落 Flash
  - **突发合并（Burst Coalescing）**：同一"高频、非安全关键"记录在窗口内重复发生时不逐条写盘，
    而是折叠为计数（`LOG_P_COUNT`），窗口到期后由 `log_task()` 汇总一条
    ⇒ **不变量：Σ `LOG_P_COUNT` = 真实发生次数**（信息不丢失，只是不再逐条占用记录）
  - **安全事件不受影响（硬约束）**：安全响应链
    `EventManager → DispenseGuard → 执行机构` **完全不经过 LogManager**
    ⇒ 日志合并**在物理上不可能**延迟或削弱安全动作；真实重量异常必须立即触发保护
