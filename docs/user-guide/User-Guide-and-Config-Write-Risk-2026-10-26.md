# Guo Feeder Web 控制台 · 用户使用说明与配置写入风险说明（2026-10-26）

> 面向**使用者**（不是开发者）。Web UI 阶段收口版。
> 术语与协议细节见 `docs/ui-v1/`；架构与决策见 `docs/architecture/`。

---

## 1. 打开与登录

1. 打开 `https://guo-feeder-pagesdev.pages.dev/app.html`
2. 登录（生产环境启用了 **Turnstile 人机验证**，需手动过一次）。
   ⚠ 登录后若长时间不操作，连接可能失效；失效时页面会提示"登录已失效"，重新登录即可。
3. 登录后**顶栏只显示两样**：当前设备（短 ID）+ 当前命令通道。
   ⇒ 完整信息（设备 ID / 别名 / registry 版本 / 通道选择 / 切换 / 刷新 / 登出）
   都在**首页的「设备与控制」区**（低频管理不再占着每一页的顶部）。

---

## 2. 命令通道（**本轮默认改了**）

| 通道 | 含义 | 你会看到什么 |
|---|---|---|
| **MQTT 直连（默认）** | 浏览器经 WSS 直接连 EMQX 发命令 | 顶栏「通道：MQTT 直连」 |
| HTTP 代理（备用） | 命令经 Pages → Worker → EMQX | 顶栏「通道：HTTP」 |

**怎么切**：「设备」页顶部「命令通道」下拉框。

**要点**：

- 默认是 **MQTT 直连**（本轮起）。显式选过 HTTP 的浏览器**不会被默认值覆盖**。
- 直连的优点：自动化运行期间能持续收到设备的执行反馈；延迟更低。
- 直连的代价（**如实告知**）：**直连不经过 Worker ⇒ 这条命令不会出现在「记录 → 审计」里**。
  需要完整审计时请切到 HTTP 通道。
- 直连不可用（账号池占满、密码刚被轮换、网络受限）时，页面会显示明确原因，
  可手动切到 HTTP 代理。**系统不会因为 HTTP 可用就悄悄把你切回 HTTP**。
- 页面切到后台超过 60 秒会自动断开直连，回到前台后下一条命令会自动重连。

## 3. 首页「当前自动化」

- 显示**当前正在执行的自动化**：设备端名称 + 状态 + **第几步 / 共几步**。
- **它是实时更新的**，不需要手动刷新。
- ⚠ **一个必须知道的事实**：设备固件**不会逐���推送"执行到第几步"**，
  所以"当前第几步"是通过**周期性读取设备运行态**得到的（执行中约 2.5 秒一次），
  终态则由设备的执行结果帧直接驱动。
- 跑完之后，首页会保留**最近一次**的结果（已完成 / 已失败 / 已超时），不会"一跑完就消失"。
- 自动化**详情页**与首页用**同一份状态**，不会出现两处说法不一致。
- 切换设备后，首页不会显示上一台设备的执行状态。

## 4. 自动化列表 / 详情 / 编辑

| 操作 | 说明 |
|---|---|
| 运行 | 会**真实驱动执行器**（可能开阀/出粮）。点开会先弹确认，并要求等 0.8 秒防误触 |
| 详情 | 看定义 + 当前运行态 |
| 编辑 | **独立页面**（不是列表内嵌）。进入后若长时间空白，点「重试加载」 |
| 删除 | 只置 `valid=false`（逻辑删除，可恢复显示），**不落盘**；落盘前重启会丢失 |
| 保存到设备（落盘） | 把内存账本写进 Flash；**落盘不重启**，新自动化在设备下次重启后加载 |

**手机端**：列表会变成卡片 —— 第一行是**名称 + 状态**，**运行按钮独占一行**（主操作），
详情/编辑/删除在下一行。状态不会被隐藏。

## 5. 设备页「系统状态」

- 每个模块（阀门 / 出粮电机 / 振动马达 / 称重 / 温湿度 / 网络）有**自己的查询按钮**。
- 点某个模块**只查那个模块**的键，**不会清空其它模块**已读到的数据。
- 「查询全部状态」被降级为**诊断入口**（29 个键 = 29 次设备往返，平时不需要）。
- **未查询** ≠ 故障：固件的状态是"单键查询"，没点就是没读。
- 如果某次查询失败，页面会明确写「上次成功值 · 本次查询失败」——
  **不会把上次的旧值装作刚查到的结果**。
- ★ **手机端布局已统一**：状态名称与值**同一屏内**显示，不用横拖表格；
  不同模块的间距一致；长值（时间戳、连接时间）会换行，**完整内容**可通过
  悬停/长按标题查看。

## 6. 配置（模块配置）

- 「设备 → 模块配置」可以逐模块查看与修改配置。
- **控件按配置语义选**：布尔 → 是/否；枚举 → 下拉（带中文标签）；整数 → 数字输入；
  字符串 → 文本框；**死参数 → 禁用并写明原因**（改了没有任何效果）。
- 数值输入框的 min/max 只在**固件真的钳位**时才出现；
  标成「界面建议，设备端不校验」的**不会**被当作硬限制（固件不会拒绝，只可能静默钳位）。
- **敏感项**（WiFi/MQTT 密码、BLE key）出厂值**不下发**，留空表示"不修改"。

### ⚠ 6.1 配置写入风险说明（**请务必读**）

| 风险 | 说明 | 你该怎么做 |
|---|---|---|
| **写配置只写内存** | 点「写入设备内存」只改 RAM，**断电/重启即丢失** | 想长期生效必须再点「保存到 Flash」；顶部会一直挂"待落盘"提示 |
| **部分键需要重启才生效** | 弹层里会写明「★ 该键需重启才生效」 | 写完记得重启设备（或用「控制 → 重启」） |
| **设备端静默钳位** | 固件**不会**拒绝超范围的值，只会**静默钳到边界** | 写完**回读确认**；UI 会显示设备实际值 |
| **硬件执行器参数很危险** | `valve.gpio_pin`（继电器引脚）、`valve.active_level`（开阀电平）、`stepper.*` 写错会**失控或常开** | 这些键目前**不在写白名单**内（如果门禁开放），不要试图绕道改 |
| **写入≠生效** | 命令被受理（202）/ 被 ACK / 入队（`s=1`）**都不代表设备执行成功** | 只有设备回 `s=0` 才算成功；页面四态卡会如实显示 |
| **版本冲突** | 别人（或你自己）先改过 ⇒ 设备拒绝并回 `version mismatch`，**你的改动不会生效** | 页面会提示，重新读取后再改 |
| **多实例并发** | 同一台设备同时打开多个页面会互相覆盖配置 | 一次只在一个页面改配置 |
| **不可逆场景未验证** | Flash 写失败 / 启动失败 / 非计划重启回滚 / 提交卡 PENDING 这四类**破坏性故障没有在生产设备上验证过** | 见 `docs/review/P4-3-Fault-Drill-and-Config-Gate-Decision-2026-10-26.md` §4.4 的人工方案与恢复步骤 |

**当前状态（2026-10-26 起）**：写通道**已开放**（用户授权）。
范围：设备限定为 `288485896ce4`；**键不限制**（任何配置键都能改）；
鉴权、类型/范围/枚举校验、版本冲突保护、命令审计**全部保留**。

> ⚠ **因此这条风险现在是真的会发生的**：
> `valve.gpio_pin`、`valve.active_level`、`stepper.*`、`vibration.*` 现在**都能改**。
> 改这些之前请确认：
> ① 弹层里的**红色危险确认**（critical 键会弹），
> ② 规格表 note（如 `valve.gpio_pin` 的 "-1 = 未配置（动作直接失败）；改错会失控或常开"），
> ③ 改完**在模块页回读**确认设备实际值 —— 固件对部分键会**静默钳位**。
> 想要更保守：把 `CONFIG_WRITE_KEYS` 改成 `"time.sync_interval_sec,time.timezone"`
> 重新部署即可（**不用改任何代码**），只留时间类低风险键。

## 6b. 首页新增的三块

| 区块 | 内容 |
|---|---|
| **设备与控制** | 设备 ID、别名、registry 版本、**命令通道选择**（MQTT 直连 / HTTP 代理）+ 两条通道的取舍说明 |
| **重启与设备切换** | 设备切换（蓝）/ 普通重启（绿）/ 强制重启（红，**有独立危险确认**）/ 刷新 / 登出（次级）；下方是**六段重启进度**（停止→下发→离线→上线→核查→完成） |
| **历史曲线** | 温度 / 湿度 / 重量三条曲线（**完整坐标轴**：横轴时间、纵轴数值与单位），**按住图面可定位任意历史点**并显示真实采样时间与数值 |

### 曲线的小知识

- 曲线数据来自设备历史遥测（**最多 200 点**）；不足 200 点就显示实际有的。
- 重量是**变化驱动 + 15 分钟兜底**上报（不是固定频率采样）⇒ 点数天然比温湿度少。
- **10 分钟内重复进首页不会重复查询设备**（有节流）；点「↻ 刷新曲线」可强制重查。
- 查询失败时**保留上次成功曲线**，并在旁边写明"最近一次查询失败"和数据的采样时间。
- 顶部显示的"上次更新"是**你这次刷新的时间**，图脚注里的"最新采样"才是**设备上报的时刻** —— 两者不同，别混。

## 7b. 「保存到 Flash」现在是**吸底悬浮条**

配置写入设备内存后、还没落盘时，页面**底部**会一直挂着一个提示条
（**待落盘 N 项 · 设备 ID · 保存到 Flash**），**滚动页面也不会消失**。
- 它在底部导航**之上**，不会挡住弹窗的确认按钮。
- 切设备时不会把上一台设备的待落盘状态带过来。
- 保存失败或设备没回执 ⇒ **提示条不会消失**，也不会谎报"已保存"。

## 8. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 顶部横幅"设备清单未确认，已禁止发送命令" | 设备清单接口失败/未加载。点横幅里的「↻ 重试加载设备清单」；仍失败就检查网络 |
| 横幅"当前设备不在可见清单中" | 这台设备对当前账号已不可见（解绑/注销/换账号）。去「设备」页重新选择 |
| 编辑页一直空白 | 点「重试加载」；还不行就返回列表再进 |
| 命令没反应 | 看四态卡：**"结果未知"** 表示没等到设备回帧（不是失败也不是成功），可「重新查询状态」（只读）或「重新下发」 |
| 模块开关显示「未确认」 | 还没从设备读到该模块的启用状态。进一次配置页会自动读一次；**未确认时不能点开关**（不知道当前是开是关，反向操作没意义） |
| 审计表「结果」列以前一直空 | 已修：以前写侧读错了字段名（协议里是 `m`），现在错误码与设备回执文本都能显示；**历史行**里没有文本的会显示 `e=N` 错误码 |
| 自动化点运行没动静 | 云端运行会**跳过第 0 步**；且设备上**没有"只停某个自动化"的入口**，要停请用「控制 → 急停」（会停全部执行器） |
