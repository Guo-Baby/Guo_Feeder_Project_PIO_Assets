### ★ 联网核实的硬约束（4 条，直接决定架构）

| # | 约束 | 影响 |
|---|---|---|
| 1 | **EMQX Serverless 只开 8883(mqtts) 与 8084(wss)**，1883/8083 不支持 | 浏览器/APP 必须 `wss://<域名>:8084/mqtt`（**URL 必带 `/mqtt` 路径**）；必须提供 **SNI**，否则拒连（错误码 `-5`）；强制 TLS，无明文选项 |
| 2 | **Cloudflare Worker 免费档 10ms CPU/请求**，但**外部网络等待(fetch)不计入 CPU** | Worker 可做"IO 为主"的转调（EMQX REST / D1 查询）；**禁止**在 Worker 内压缩/解析大 JSON、长循环 → 会报 `Error 1102`。100k req/天 |
| 3 | **D1 免费 100,000 rows write/天**；**KV 仅 1,000 write/天** | ⇒ **历史数据必须落 D1，绝不能用 KV**（用 KV 当天就爆） |
| 4 | EMQX **数据集成（规则引擎 → HTTP Action）在 Serverless 可用**，Beta 期免费 | D1 落历史走"EMQX 规则 → HTTP → ingest Worker → D1"，**不占设备流量、设备侧零改动** |

### ★ 架构定论：控制平面 / 数据平面分离

- **控制平面（低频，走 Worker）**：登录 → `GET /api/device/<id>/credential` → Worker 校验 JWT + 查绑定关系(D1) → 返回**一次性 MQTT 临时凭据**（url/user/pass/exp）
- **数据平面（高频，不经 Worker）**：APP 用临时凭据 **WSS 8084 直连 EMQX**，订阅/发布
- **落库（异步）**：EMQX 数据集成 → ingest Worker → D1
- 理由：高频遥测**完全不消耗 Worker 请求额度**；延迟少一跳；永不下发设备级长期凭据
- ⚠️ 唯一注意点：EMQX 数据集成回写**会计入 Worker 请求数**（单设备 10s 上报一次 = 8640 次/天 ≈ 额度 8.6%；**多设备必须提前算账**）

### ★ Homie 5 与 Capability Registry 的映射（复用度极高）

| 现状 | Homie 5 对应 | 备注 |
|---|---|---|
| `capability_registry` Action 列表 | Node + Property | 几乎直接映射 |
| `capability_export_action_registry()` | `$description` JSON | 换一层序列化 |
| `registry.version`（uint32 递增） | `$description.version`（整数递增） | **语义天然吻合**（Homie 允许非连续，甚至时间戳） |
| `workflow.variant` / `object_version` | `$description` 版本 | 已具备 |
| `LOG_REG_REBUILT` 事件 | 触发重发 `$description` | 埋点已有，挂回调即可 |

**Homie 5 规范要点（照抄）**：
- 根主题 `homie/5/<device-id>/`；`homie` 域**可自定义**，**版本段 `5` 不可改**
- 控制器默认发现：订阅 `+/5/+/$state`
- `$state` **必须 retained**，**LWT = `lost`**；生命周期 `init` → **`ready`**（`online` 是 Homie 4 旧值，5 已改）
- `$description` **retained**，且**仅允许在 `$state` = `init`/`disconnected`/`lost` 时变更**
- 空 payload on `$state` = 设备注销
- 写属性走 `<node>/<prop>/set`
- 规范原文："An empty string ("") is not a valid payload"（DateTime 用 ISO 8601，Duration 用 `PTxHxMxS`）

**落地方案（不碰核心）**：新增 `homie_bridge`（放 CloudManager 内），**只做序列化/主题映射**，写入方向统一转成现有命令 → 走 **CommandManager**（复用既有 `cmd_id` 去重 + `v`/`k` 校验）。**不新增 Action/Trigger/EventId/ParamId**（遵守冻结约定）。预估：新模块 ~250 行 + `cloud_manager.cpp` ~40 行 + `main.cpp` ~10 行 + `mqtt.json` 2 字段

**Homie domain 建议选 `homie` 而非 `guofeeder`**：MQTT-Tiles 默认按 `homie` 做发现，改成自定义域反而要改前端源码。旧 `guo_feeder/up|down|log` **保留不动**（Protocol V2.0 冻结），Homie 树作为**并列的、面向 UI 的投影** —— 即使 Homie 层出问题，设备主链路不受影响

### ★ 前端选型：MQTT-Tiles（而非 Crouton）

- MQTT-Tiles：MIT、Vue2+Quasar1、**支持任意 WSS broker**、tile 粒度 = Homie property 粒度（映射几乎不用设计）
- 必须自己补：**自动发现逻辑**（它没有）—— 连接后 `subscribe('homie/5/+/$state')` → `ready` → 取 `$description` → 动态生成 tile。**这正是自描述的价值：设备加能力，UI 自动出现**
- 改版**必做项**（非可选）：MQTT-Tiles 静态 tile 无法为每条命令生成唯一 `id`，而设备**对重复 `id` 静默丢弃**（`MQTT_DUP_CACHE_SIZE=10` / `TTL 30s`）⇒ button tile 每次发布必须生成唯一 `id`

### ★ 安卓端：先 WebView 壳，库选 HiveMQ

- **Eclipse Paho Android 2018 年后停更**（需 Jetifier、Android 10+ 兼容问题、无 MQTT 5.0）⇒ **弃用**
- **HiveMQ MQTT Client**（`com.hivemq:hivemq-mqtt-client`）：支持 **MQTT 5.0**、异步非阻塞、内置指数退避重连、不依赖旧 support 库 ⇒ **新项目直接用**
- 路线：先 WebView 套 MQTT-Tiles 页面（一套代码两端）+ 通知 → 需要后台常驻/蓝牙配网时再上原生
