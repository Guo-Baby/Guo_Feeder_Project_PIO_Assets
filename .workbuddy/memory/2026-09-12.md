## Capability Registry 临时缓冲改 PSRAM（8a1e4c4）

起因：用户指出"大的对象放不下可以放在 PSRAM 中"。此前 `beff2d3` 只把
栈上 2.4KB 挪到**内部 RAM 堆**（`MALLOC_CAP_8BIT`），没用上 PSRAM。

- 实测确认 PSRAM 可用：`PSRAM size: 8386279 / free: 8386035`（8MB，N16R8），
  platformio.ini 已配 `board_build.arduino.memory_type = qio_opi` + `psram_type = opi`。
- 新增 `registry_buf_alloc(size, bool *all_psram)`：`MALLOC_CAP_SPIRAM` 优先，
  失败回退 `MALLOC_CAP_8BIT`；与 `workflow.cpp:782` / `workflow_storage.cpp:1481`
  既有范式一致（**项目统一范式：大对象 PSRAM 优先、回退 DRAM**）。
- 日志：`[CapRegistry] sync buf 2328 B in PSRAM (hwm=9828)`。
- 顺带修掉 `load_registry_file()` 里**栈上** `CapabilityRegistryTable tmp`（约 800B，
  含 32 个 String），改为直接写调用方缓冲区（唯一调用点已先 `table_reset`，安全）。
- `table_reset()` 补清 `object_version`（原遗漏，未用槽位残留旧值）。

### 关键区分（易混淆）
**栈永远在内部 RAM，PSRAM 只能用于堆。** 所以"栈溢出"的正确解法顺序是：
① 大对象从栈移到堆（必要）→ ② 堆分配优先 PSRAM（优化，省内部 RAM）。
`-DARDUINO_LOOP_STACK_SIZE=16384` 仍需保留，PSRAM 救不了栈。

## 协议缺口（已解决 → 见下方"Workflow 云端同步完善"）
`workflow.delete` 只做逻辑删（valid=false + variant++），此前 `workflow.list`
不返回任何 deleted/valid 标记，云端在"删完→重启前"的窗口里会认为对象还活着。
**已按需求文档 §5 解决**：`workflow.list` 每项 + `workflow.get` 顶层均返回 `valid`。

## ArduinoJson 与 PSRAM
ArduinoJson 7.4.3 **不含** PSRAM 支持（`grep -rl PSRAM src/` 无结果），
所有 `JsonDocument` 缓冲仍占内部 RAM。若要迁移需自定义 Allocator
（`BasicJsonDocument<PsramAllocator>`），属较大改动且 MQTT 解析路径会变慢，未做。

### 定版的协议要点（写云端/UI 必看）
- `workflow.list` 每项 = `{stable_id, id, variant, valid}`；`workflow.get` 的
  `valid` 放在 `workflow{}` **外面**（`workflow{}` 要能原样回传 `set`）。
- `workflow.sync_info` 只回 `registry_version / registry_checksum / count / dirty`。
- `set` 幂等：canonical 文本比较（字段定序 + 参数按 name 排序 + 值带 `i/f/b/s` 前缀），
  内容完全一致 → 不 `variant++`、`changed:false`。
- `delete` 逻辑删：`valid=false` + `variant++`，**不物理删**、不杀 Runtime；
  重启前 `list` 仍可见（这是刻意设计，让云端知道"被删了"而不是"消失了"）。
- `save` 是**全局** Dirty 落盘：任何一个失败 → 不 clear dirty、不 release Critical、
  返回错误码 10，可重试；全部成功才清零；`dirty=false` 时**不得**空转重启。

### 三个必须记住的语义（极易踩）
1. **`stable_id` ≠ Slot 编号**：= 按 `runtime_id` 字符串升序排序后的下标
   （`sort_capability_mapping`，capability_registry.cpp:468）。所以新增/改名一个
   字母序靠前的 id，会让**后面所有对象**的 stable_id 整体平移。
   实测：加 `cm_a` 后 `daily_valve_test` 从 #0 变 #1。
   ⇒ 云端必须以 `id` 为业务主键，`stable_id` 只作定位；`registry_version` 变了就重建映射。
2. **`enable` 缺省值两条路径不一致**：JSON 导入缺省 `true`，BIN 加载缺省 `false`。
   建议云端永远显式传 `enable`。（未改代码）
3. **`step.id` 写错不会报错**：未注册的 id 会被安静保存但永不执行。
   云端必须用设备注册清单校验。

### 本次修掉的高危缺陷（dd49512）
`workflow_pick_object()` 原来在 `pl["workflow"]` 缺失但 `pl["id"]` 存在时，
把**整个 payload** 当完整 Workflow。而 `set` 的定位字段同样是 `p.id`，于是
`p:{"id":"WF1"}`（只想定位）→ 目标对象 steps 被**静默清空**。
修复：内容必须嵌套在 `p.workflow`；平铺形态返回错误码 6。
